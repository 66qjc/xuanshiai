## 二、Phase 4/5 启动条件（P-04 / S-06 / C-06 / 学习排序）

> 以下仅记录启动条件，本期不实现。只有全部满足才可另立计划启用；未获批前所有 AI 开关保持关闭。

### P-04 语音/ASR（Phase 4）

- 产品和合规书面批准语音/转写用途、语言、地域、原始音频与 transcript 保留期、导出和删除 API。
- Provider 完成 DPA/数据出境/训练用途审查，且可以按 task/user 证明删除。
- 音频上传有格式、时长、病毒、内容治理和访问控制；失败可稳定回退文字输入，不重复扣费。
- 未满足前不提供任何音频路由（`docs/api/AI画像.md` §16）。

### S-06 语义召回（Phase 4）

- embedding 只用于已确认且允许检索的字段，索引有 `projection_version`、`privacy_revision` 和撤回即时过滤。
- MySQL 可见性和硬条件仍是主门禁；模型输出不能成为 SQL/列名/`ORDER BY`/表名。
- 向量存储、索引与 ANN 检索组件须单独评审（延迟、成本、删除传播、保留期），未批准前 `ai_search_enabled` 保持关闭。
- 旧 `user_feature_vector.interest_vector` 不作为 embedding 使用；一期不接 ANN。

### C-06 兼容度质量评估（Phase 4）

- 先做人工标注、离线回放、覆盖/安全/公平性/成本/延迟报告，不自动改变规则权重。
- 新兼容度只写 shadow（`display_eligible=false`、`experiment_bucket=shadow`），不影响推荐排序与用户动作。

### Phase 5 学习排序

- 行为事件字典、明确用途授权、去标识化训练集、人工标注、校准、群体公平性评估、独立合规审查、在线监控和一键回滚全部就绪。
- 训练标签至少区分查看、喜欢、申请、接受、聊天、举报和拉黑，不把一次点击、会员购买或关系结果承诺混成单一标签。
- 学习排序永远运行在 `CandidateVisibilityService`、硬条件和账号状态之后。

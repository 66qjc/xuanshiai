# 首页与“我的”页面后端接口对接缺口清单

> 目标：给后端开发使用。本文对比当前前端首页、我的页面及其子页面与 `xuanshiai/app` 的实际 FastAPI 路由、Schema 和当前调用方式。
>
> 接口路径以下均省略统一前缀 `/api/v1`。前端真实环境的请求基地址应为：`{baseURL}/api/v1`。
>
> 结论先行：当前后端已有推荐、浏览记录、访客、收藏、申请、资料、举报、拉黑等基础能力，但前端仍有旧 `/user/*` 路径和大量静态/mock 数据；爆灯支付、置顶、谁收藏我、爆灯记录和我的页面统计仍缺少可直接消费的后端接口或字段。

## 1. 优先级定义

| 优先级 | 含义 | 后端处理要求 |
| --- | --- | --- |
| P0 | 当前会 404、410、422，或支付/核心流程无法完成 | 本轮必须确认并修复，或明确由前端迁移 |
| P1 | 路由存在，但前端没有接入、返回字段不足或无法支持页面 | 排入本轮联调 |
| P2 | 非核心运营内容、统计增强或后续能力 | 可排期，不阻塞首页和我的页面主流程 |

## 2. P0：必须先处理

### 2.1 首页旧 `/user/*` 路径与后端路由不一致

前端文件：`api/user.uts:182`、`api/user.uts:199`、`api/user.uts:212`、`api/user.uts:256`、`api/user.uts:273`、`api/user.uts:433`、`api/user.uts:596`。

| 前端当前请求 | 后端现有接口 | 问题 | 建议 |
| --- | --- | --- | --- |
| `GET /user/recommend` | `GET /discovery/recommendations` | 真实环境会 404 | 前端迁移到 discovery，不建议后端长期保留旧路由 |
| `GET /user/recommend/list` | `GET /discovery/recommendations` | 后端没有 list 路由 | 前端统一使用分页接口 |
| `GET /user/square` | `GET /discovery/plaza` | 真实环境会 404 | 前端迁移到 `/discovery/plaza` |
| `GET /user/detail?userId=` | `GET /users/{user_id}/profile` | 路径和参数位置不同 | 前端迁移为 `/users/{id}/profile` |
| `GET /user/me` | `GET /users/me/profile` | 路径不同 | 前端统一使用现有接口 |
| `POST /user/apply` | `POST /discovery/applications/{target_id}` | 路径和参数名不同 | 前端发送 `{ "message": "..." }` |
| `POST /user/like` | `PUT/DELETE /users/{target_id}/like` | 后端是幂等启用/取消，前端旧接口是 toggle | 前端先读取状态，再按意图调用 PUT 或 DELETE |

后端如需临时兼容旧版本，可以增加兼容路由，但必须复用 discovery/users service，不能复制一套业务逻辑。推荐验收：关闭前端 mock 后，首页推荐、广场、详情、申请认识、喜欢/取消喜欢均不再出现 404。

### 2.2 编辑资料请求会触发 422 或丢字段

前端文件：`pagesSub/userExtra/user/edit.uvue:549`。

当前前端 payload 的关键字段：

```json
{
  "gender": 1,
  "birthday": "1998-05-15",
  "is_married": 1,
  "height": 165,
  "weight": 48,
  "occupation": "插画师",
  "industry": "文化创意",
  "education_level": 3,
  "income_range": "30-50w",
  "residence_city_code": "浙江省 杭州市 西湖区",
  "hometown": "浙江省 杭州市 西湖区",
  "company": "某公司",
  "self_intro": "...",
  "interest_tags": [],
  "personality_tags": [],
  "mbti": "INFJ",
  "tag_selections": {}
}
```

后端 `xuanshiai/app/schemas/auth.py:85` 的 `ProfileUpdateRequest` 当前契约：

- 收入字段是 `income: float`，不是 `income_range: string`。
- 地址必须拆为 `residence_province_code`、`residence_city_code`、`residence_district_code`；家乡同理，不能传拼接地址到 `residence_city_code`。
- 没有 `weight` 字段，前端体重会被忽略或触发禁止额外字段校验，需统一方案。
- `height` 当前限制为 `150..200`，而产品和前端选择器使用 `140..220`。
- `self_intro` 后端上限 1000 字；前端产品要求上限 500 字，需要统一为 500 或明确前端改为 1000。
- `interest_tags`、`personality_tags` 传非空时必须各 3 至 5 个；前端未满 3 个会传 `null`，后端需确认这是“清空”还是“未修改”。
- `tag_selections` 中每个分类必须非空且最多 5 个，空对象的语义需明确。

建议后端和前端二选一后固定契约，推荐如下：

1. 后端新增 `weight: int | null`，范围 `40..120`。
2. 后端将 `height` 改为 `140..220`，并同步资料库校验。
3. 收入使用枚举字符串 `income_range`：`lt_10w`、`10_20w`、`30_50w`、`50_100w`、`gt_100w`、`secret`；或者前端改传数值 `income`，但不能继续混用。
4. 地址只接收省、市、区 code，返回时同时返回名称或由前端用 `location.json` 映射。
5. 明确 PATCH 语义：字段缺省表示不修改，字段为 `null` 表示清空；空标签是否允许清空必须写入接口文档。
6. 前后端统一 `self_intro` 最大长度。推荐改为 500。

### 2.3 爆灯支付接口不存在，现有爆灯接口也不是支付接口

前端文件：`api/spotlight.uts:56`。

前端真实请求：

```http
POST /spotlights/payments
Content-Type: application/json

{"target_user_id": 123}
```

当前后端只有 `POST /discovery/superlikes/{target_id}`，并且要求 `Idempotency-Key` Header（至少 8 位）。该接口直接执行爆灯业务，不等同于微信支付订单；后端没有 `/spotlights/payments` 路由。

推荐后端提供统一支付链路，避免前端伪造已支付状态：

- `POST /discovery/superlikes/{target_id}/orders`：创建爆灯支付订单，要求 `Idempotency-Key`。
- `GET /discovery/superlikes/orders/{order_no}`：查询本人订单状态。
- `POST /payments/wechat/callback`：复用现有微信回调，支付成功后写入爆灯记录。
- 或明确前端直接调用现有 `POST /discovery/superlikes/{target_id}`，并返回真实扣费/支付状态；此时必须补充订单查询能力。

至少确认返回：`order_no`、`target_user_id`、`amount`、`status`、`payment_required`、`pay_params`（如需要微信调起支付）、`created_at`、`expire_at`。重复 Idempotency-Key 必须返回同一订单，不能重复扣费。

### 2.4 置顶完全没有真实后端接口

前端文件：`api/top-placement.uts:46`、`api/top-placement.uts:58`。

当前 `getTopPlacementStatus()` 和 `payTopPlacement()` 只读写 `mock/top-placement.uts` 与本地 Storage；没有调用后端。首页入口在 `pages/index/index.uvue:283`，页面路径为 `pagesSub/userExtra/index/top-placement`。

如该功能继续保留，后端至少需要：

- `GET /users/me/boost/status`：返回 `active`、`remaining_days`、`expires_at`、`order_no`。
- `GET /boost/packages`：返回套餐 `id`、`name`、`days`、`price`、`recommended`。
- `POST /boost/orders`：请求 `{ "package_code": "..." }`，要求 `Idempotency-Key`。
- `GET /boost/orders/{order_no}`：查询订单。
- 支付成功后写入用户置顶有效期，并在推荐/广场排序中使用 `is_boosted`。

如果本期不做置顶，应由前端隐藏入口并从验收范围移除，不能让页面看起来支付成功但只写本地数据。

## 3. P1：接口已有，但页面未接入或返回不足

### 3.1 我的页面没有使用聚合接口，统计是静态数据

前端文件：`pages/profile/profile.uvue:108`、`pages/profile/profile.uvue:113`。

当前昵称、VIP 进度和四个统计值为静态值。后端已有 `GET /users/me/overview`，返回 `ProfileOverviewResponse`：

- `nickname`、`avatar`、`completion_score`
- `certification`、`membership`
- `unread_notification_count`
- `incoming_application_count`、`outgoing_application_count`
- `match_count`、`shortcuts`

建议前端接入该接口；后端确认统计含义：当前“我的申请”需要同时展示发出/收到，不能只返回一个数字。建议 overview 增加：

```json
{
  "visitor_count": 0,
  "favorite_count": 0,
  "favorite_received_count": 0,
  "superlike_sent_count": 0,
  "superlike_received_count": 0
}
```

如果不希望扩大 overview，则新增 `GET /users/me/stats`，保持分页列表与首页角标使用同一统计口径。

### 3.2 历史记录和谁看过我页面目前是静态数据

前端文件：`pagesSub/profileExtra/history.uvue:49`、`pagesSub/profileExtra/visitors.uvue:16`。

后端已有：

- `GET /discovery/browse-history?page=1&page_size=20`
- `GET /discovery/visitors?page=1&page_size=20`

返回模型已经包含首页卡片需要的用户信息：`target`、`viewed_at`、分页字段；访客额外有 `can_view_details`、`count`。

要求前端替换静态数组，并由后端确认以下规则：VIP/非 VIP 可见哪些字段、匿名浏览如何展示、被拉黑/注销用户是否过滤、`count` 是总访客数还是当前页数量。页面空、加载、网络失败和无权限状态要按接口结果显示。

### 3.3 我的收藏有“我的收藏”接口，但“谁收藏我”接口缺失

前端文件：`pagesSub/profileExtra/favorites.uvue`。

后端已有：

- `GET /discovery/favorites?page=1&page_size=20`：我的收藏。
- `PUT /discovery/favorites/{target_id}`：收藏。
- `DELETE /discovery/favorites/{target_id}`：取消收藏。

页面第二个 Tab“谁收藏我”不能使用已废弃的 `GET /relations/liked-by`，该接口当前返回 410。请新增推荐接口：

```http
GET /discovery/favorites/received?page=1&page_size=20
```

建议返回与 `FavoritePage` 相同的分页结构：`items`、`page`、`page_size`、`total`、`has_more`，并明确实名、VIP、隐私设置、拉黑和注销过滤规则。不要把“喜欢”误当作对方可见的申请认识；返回字段应标识 `is_favorite` 和关系方向。

### 3.4 爆灯记录页面没有列表接口

前端文件：`pagesSub/profileExtra/spotlights.uvue`；支付封装：`api/spotlight.uts:15`。

页面有“我发出的”和“谁给我爆灯”两个 Tab，但当前仅使用静态空状态。后端已有写入接口 `POST /discovery/superlikes/{target_id}`，没有查询接口。请新增：

- `GET /discovery/superlikes/sent?page=1&page_size=20`
- `GET /discovery/superlikes/received?page=1&page_size=20`

返回至少包含：记录 id、对方用户卡片、方向、状态、创建时间、是否已匹配、支付订单号（仅本人可见）和分页字段。重复提交、退款、目标用户注销或拉黑后的展示规则需明确。

### 3.5 我的申请页面未接入现有申请接口

前端文件：`pagesSub/profileExtra/applications.uvue:16`。

后端已有：

- `GET /discovery/applications/outgoing`
- `GET /discovery/applications/incoming`
- `POST /discovery/applications/{application_id}/accept`
- `POST /discovery/applications/{application_id}/reject`

当前页面的 `applications`、`receivedApplications` 是静态数组。前端应改用以上接口。现有 `ApplicationResponse` 只有用户 id、留言、状态、时间，没有对方头像、昵称、年龄、城市等页面直接展示字段。推荐后端把 `from_user` / `to_user` 卡片信息内嵌返回，或增加批量用户摘要字段，否则前端会为每条记录额外请求详情并造成瀑布请求。

同意/拒绝接口需要确认：只有收件人可操作、重复操作返回 409、状态值 0/1/2/3 的含义、成功后聊天权限何时开启。拒绝理由前端目前没有发送，若需要则发送 `{ "reason": "..." }`。

### 3.6 首页推荐卡片的数据字段不足以支撑全部 UI

后端 `DiscoveryCard` 已返回：头像、年龄、身高、学历、职业、城市、收入、距离、婚姻、在线状态、MBTI、兴趣标签、认证标签、匹配分和匹配原因。

首页设计还展示背景墙、生活照、自我介绍、家庭背景/爱情观问答、个人动态、分享海报等深度信息。现有详情接口 `GET /users/{user_id}/profile` 返回 `PublicProfileResponse`，其中 `profile` 可为空且受权限控制；后端需要确认：

- 推荐列表只返回卡片字段，不要把大图和深度问答塞进列表。
- 详情接口在无权限时返回 `profile: null`、`detail_locked` 和可展示的公开字段。
- 未填写的深度问答不要返回空的假数据。
- `background_wall`、`photos`、`self_intro`、深度问答和动态是否需要补充到 `ProfileResponse` 或独立详情接口。
- `match_score` / `match_reason` 是否是真实算法结果，不能以固定 mock 文案代替。

### 3.7 首页搜索和筛选参数要按 discovery Schema 发送

后端已有：

- `GET /discovery/recommendations`
- `GET /discovery/plaza`
- `GET /discovery/search`
- `GET /discovery/filters/options`

筛选字段是 `gender`、`age_min/max`、`province_code`、`city_code`、`district_code`、`marriage_status`、`education_min`、`height_min/max`、`income_min/max`、`pure_free`、`page`、`page_size`；页大小最大 20。搜索至少要提供 `nickname` 或 `tag`，不能传空关键词。

请后端补充确认收入区间、学历枚举、婚姻状态枚举和城市 code 的正式字典；前端选择器和 `location.json` 必须使用同一套 code。

### 3.8 举报和拉黑路径存在，但请求体/响应处理需要联调

前端调用位置：`api/community.uts:2627`、`api/community.uts:2671`、`api/community.uts:3516`。

后端已有：

- `POST /security/reports/{target_id}`，请求体必须包含 `type`，可选 `description`、`images`。
- `PUT /security/blocks/{target_id}`，可选请求体 `{ "reason": "..." }`，204。
- `DELETE /security/blocks/{target_id}`，204。

请后端确认举报类型字典和前端文案映射；前端拉黑目前可能发送空对象，后端的 `BlockRequest` 已允许空 body，但网关不能把空 body 误判为 422。前端 `request.uts` 也必须正确处理 204 无响应体。验收需覆盖重复拉黑、自己拉黑自己、已注销用户、举报重复提交和拉黑后首页列表过滤。

## 4. P2：可选接口或产品确认项

### 4.1 关于我们、客服

前端 `api/about.uts` 和客服页面目前为本地静态内容/Toast，没有真实后端接口。若需要运营后台可编辑，建议：

- `GET /content/about`
- `GET /support/faqs`
- `POST /support/sessions/messages`

否则明确本期不接后端，避免把静态页面误列为接口缺失。

### 4.2 VIP 页面

后端已有：

- `GET /membership/packages`
- `GET /users/me/membership`
- `GET /users/me/membership/history`
- `POST /membership/orders`，请求 `{ "package_code": "monthly" }`，必须带 `Idempotency-Key`。
- `GET /membership/orders/{order_no}`

请确认前端会员页使用 `package_code`，不要把页面显示的 7 天/90 天文本直接当作价格或订单参数。订单返回需要能支持支付弹窗：`order_no`、`amount`、`status`、`payment_required`、`expire_at`，以及微信支付调起参数（若由后端生成）。另外后端会员服务文档已指出订单 `product_type` 与套餐 code 的历史问题，需要在联调前修复并补测试。

## 5. 建议的最小后端交付顺序

1. 确认统一前缀和认证方式，关闭前端 mock 后修复首页旧路径对应的前端迁移问题。
2. 修复资料更新 Schema：体重、身高范围、收入枚举、地址 code、空值语义。
3. 提供爆灯支付/订单和置顶订单接口，或明确从本期产品范围移除对应入口。
4. 增加收藏收到列表、爆灯发出/收到列表，并补齐我的页面统计字段。
5. 在申请、浏览记录、访客接口中提供可直接展示的用户摘要，验证分页和权限。
6. 联调举报、拉黑、204 响应和幂等键，最后回归首页和我的页面全部子页面。

## 6. 联调验收用例

- 未登录访问首页：按项目登录策略跳转欢迎/登录页，不请求需要登录的 discovery 接口。
- 已登录且无 mock：推荐、广场、搜索、筛选、详情均返回真实数据，分页可继续加载。
- 编辑资料：身高 140 和 220 可保存，139/221 被拒绝；体重 40 和 120 可保存；地址保存为三个 code，重新打开能回显省市区。
- 首页申请认识：实名用户发送留言成功；重复申请不重复扣次数；未实名、额度耗尽分别返回明确错误。
- 喜欢、取消喜欢、收藏、取消收藏：重复点击状态幂等，列表和卡片状态一致。
- 我的页面：昵称、头像、VIP、申请、访客、收藏、爆灯统计来自接口，不出现固定演示数字。
- 历史记录、谁看过我、我的收藏、谁收藏我、我的爆灯、我的申请：空列表、分页、网络失败、无权限和真实列表均可展示。
- 爆灯和会员支付：重复点击不重复创建订单；支付中可查询；回调后状态和权益一致；不能只写本地 Storage。
- 举报/拉黑：请求体符合 Schema；204 不被解析为 JSON；成功后列表过滤且可解除拉黑。

## 0. 复核结论（2026-08-01）

> 本节是对本文后续历史记录的最终修订，以当前前端代码和 `xuanshiai/app` 路由为准。后端开发优先阅读本节；如果与后文旧记录冲突，以本节为准。

### 0.1 请求前缀必须先确认

- 后端代码中的逻辑接口前缀是 `/api/v1`。
- 当前前端配置实际拼接为 `http://101.37.157.23:8000/api/api/v1`，原因是线上 Swagger Server base 被配置为 `/api`。
- 请后端确认线上最终可访问地址到底是 `/api/api/v1/...` 还是 `/api/v1/...`，并统一 Swagger、反向代理和前端配置。不要同时保留两套不一致的前缀。

### 0.2 已由前端接入真实接口，不属于后端缺失

以下页面/功能已经走真实 API（`USE_MOCK = false`）：首页推荐、广场、搜索、用户详情、资料读取与保存、我的页面聚合信息、浏览记录、谁看过我、我的收藏、我的申请、向我申请、申请同意/拒绝、VIP 套餐读取、举报、拉黑/解除拉黑。

`api/user.uts` 中的 `/user/*` 仅存在于本地 Mock 分支，真实环境不会请求这些旧路径，不需要后端为 `/user/*` 增加兼容路由。

### 0.3 确认缺失的接口

| 优先级 | 接口 | 用途 | 当前问题 |
| --- | --- | --- | --- |
| P0 | `GET /discovery/favorites/received?page=1&page_size=20` | 谁收藏我 | 后端没有收到收藏列表接口，页面第二个 Tab 无法展示真实数据 |
| P0 | `GET /discovery/superlikes/sent?page=1&page_size=20` | 我的爆灯 | 后端只有创建爆灯接口，没有发出记录查询 |
| P0 | `GET /discovery/superlikes/received?page=1&page_size=20` | 谁给我爆灯 | 后端没有收到爆灯记录查询 |
| P0 | 置顶状态、套餐、订单和订单查询接口 | 首页“我要置顶” | 当前前端只写本地 Mock/Storage，后端没有真实置顶支付链路 |
| P0 | `POST /spotlights/payments` 或正式订单链路 | 爆灯支付 | 当前前端封装请求该路径，但后端没有该路由；现有 `POST /discovery/superlikes/{target_id}` 是免费/额度业务，不是微信支付订单 |

收到列表接口至少返回 `items/page/page_size/total/has_more`，每条记录应内嵌对方用户摘要：`user_id/nickname/avatar/age/city_code`，以及关系方向、状态、`created_at`。不要要求前端为每条记录额外请求用户详情。

### 0.4 已有接口但字段不足或参数不一致

1. `GET /users/me/overview` 当前 Schema 只有申请数、匹配数等字段；前端页面还需要 `visitor_count`、`favorite_count`、`favorite_received_count`、`superlike_sent_count`、`superlike_received_count`。请补齐字段，或提供 `GET /users/me/stats`。
2. `GET /discovery/applications/incoming|outgoing` 的 `ApplicationResponse` 只有双方用户 ID、留言、状态和时间。请内嵌 `from_user/to_user` 用户摘要，否则前端会产生详情瀑布请求。
3. 首页卡片目前可用字段包括头像、昵称、年龄、身高、学历、职业、城市、收入、距离、婚姻、在线状态、MBTI、兴趣标签、认证标签、匹配分和匹配理由；背景墙、生活照、自我介绍、深度问答、动态等内容应由详情接口明确返回，不能在推荐卡片中用固定值补齐。
4. `PATCH /users/me/profile` 当前缺少 `weight`；`height` 后端范围是 `150..200`，前端产品范围是 `140..220`；`self_intro` 后端上限是 1000，产品要求 500；`income` 当前是数值，但前端收入选择器是区间枚举。请统一契约后再联调。
5. 资料地址必须使用 `residence_province_code/residence_city_code/residence_district_code` 和 `hometown_province_code/hometown_city_code/hometown_district_code`。前端选择器使用省市区 code，不能只传拼接后的中文地址。
6. 标签字段非空时后端要求每类 3 至 5 个，且必须来自后端标签字典；请确认空数组/null 的 PATCH 语义是清空还是不修改。

### 0.5 当前文档中的路径修正

- 后端实际路由是 `GET /discovery/filter-options`，不是旧文档中写的 `GET /discovery/filters/options`。
- 过滤项接口当前返回 `genders/marriage_statuses/education_levels/cities`；如果前端需要省市区联动，请补充正式 code 字段或明确使用区域接口。
- `GET /relations/liked-by` 已废弃并返回 410，不要用它实现“谁收藏我”；收藏与喜欢必须按产品定义区分。

### 0.6 后端交付验收标准

- 关闭前端 Mock 后，首页推荐/广场/搜索/详情和我的页面首屏不出现 404、422。
- 我的页面昵称、头像、资料完成度、VIP、申请、访客、收藏、爆灯统计全部来自接口，不返回固定演示数字。
- 资料保存支持体重、140--220 身高、500 字自我介绍、收入区间和完整省市区 code。
- 收藏收到、爆灯发出/收到、置顶订单和爆灯支付链路有可查询的真实数据，并支持分页、幂等和明确错误码。

# 接口契约补全（2026-08-05）

本文档补充现有模块文档中缺少的字段级接口契约。所有路径均已自动带有 `/api/v1` 前缀；除特别注明外，成功响应为 JSON，错误响应格式为 `{"detail":"错误原因"}`。每个接口均单独描述，不将多个接口合并为一个请求或返回契约。

## 一、财务与结算

### 1. `POST /api/v1/finance/orders` 创建待支付订单

**权限与请求信息**：需登录；`Content-Type: application/json`；成功 `201 Created`。该接口只创建订单，不代表已支付。

**请求参数**：

| 参数 | 位置 | 类型 | 必填 | 规则 | 含义 |
| --- | --- | --- | --- | --- | --- |
| `product_type` | body | integer | 是 | `1~32` | 业务商品类型编码 |
| `product_name` | body | string | 是 | 1~128 字符 | 下单时固化的商品名称 |
| `amount` | body | decimal string | 是 | `>0` 且不超过 `1000000.00`，最多 2 位小数 | 订单金额，服务端按分保存 |

**请求示例**：`{"product_type":1,"product_name":"会员服务","amount":"99.00"}`。非法示例：`{"product_type":0,"product_name":"","amount":"-1"}`，返回 `422`。

**返回参数与示例**：返回 `PaymentOrderResponse`：`id` 订单 ID；`order_no` 订单号；`user_id` 下单用户；`product_type`、`product_name`、`amount` 商品信息；`status` 状态（`0`待支付、`1`已支付、`2`已关闭、`3`已退款）；`pay_time` 支付时间，未支付为 `null`；`created_at` 创建时间。

```json
{"id":101,"order_no":"FO202608050001","user_id":23,"product_type":1,"product_name":"会员服务","amount":"99.00","status":0,"pay_time":null,"created_at":"2026-08-05T10:00:00"}
```

**规则与错误**：同一订单只能从待支付进入已支付；真实支付回调负责生产环境履约。`401`未登录，`409`重复或状态冲突，`422`字段校验失败，`503`支付/数据库服务不可用。

### 2. `GET /api/v1/finance/balance` 查询余额

**权限与请求信息**：需登录；无请求体；成功 `200 OK`。

**请求参数**：无 path、query、body 参数。请求示例：`GET /api/v1/finance/balance`，Header 为 `Authorization: Bearer <access_token>`。

**返回参数与示例**：`account_type` 账户类型；`account_id` 账户 ID；`pending_amount` 待结算金额；`available_amount` 可提现金额。

```json
{"account_type":"user","account_id":23,"pending_amount":"30.00","available_amount":"70.00"}
```

**规则与错误**：无账本记录时两个金额均为 `"0.00"`；`401`未登录，`503`数据库不可用。

### 3. `GET /api/v1/finance/commission-entries` 查询分成明细

**权限与请求信息**：需登录；无请求体；成功 `200 OK`。

**请求参数**：无参数。请求示例：`GET /api/v1/finance/commission-entries`。

**返回参数与示例**：返回数组；每项 `id` 流水 ID、`order_id` 来源订单、`beneficiary_type` 受益方类型、`beneficiary_id` 受益方 ID、`base_amount` 分成基数、`amount` 分成金额、`status`（`PENDING`/`AVAILABLE`/`REVERSED`）、`created_at` 创建时间。

```json
[{"id":8,"order_id":101,"beneficiary_type":"promoter","beneficiary_id":7,"base_amount":"99.00","amount":"9.90","status":"PENDING","created_at":"2026-08-05T10:01:00"}]
```

**空结果**：没有分成时返回 `[]`，不返回 `null`。`401`未登录，`503`数据库不可用。

### 4. `POST /api/v1/finance/withdrawals` 申请提现

**权限与请求信息**：需登录；JSON；成功 `201 Created`。

**请求参数**：`amount` body decimal，`>0`且最多 2 位小数，提现金额；`payee_masked` body string，1~128 字符，脱敏后的收款方标识，禁止提交密码、完整银行卡号或支付密钥。

**请求示例**：`{"amount":"50.00","payee_masked":"wx***23"}`。非法示例：`{"amount":"0","payee_masked":""}`。

**返回参数与示例**：`id`申请 ID；`account_type`、`account_id`账户；`amount`金额；`status`通常为 `PENDING_REVIEW`；`payee_masked`脱敏收款方；`failure_reason`失败原因，无则 `null`；`created_at`、`updated_at`时间。

```json
{"id":12,"account_type":"user","account_id":23,"amount":"50.00","status":"PENDING_REVIEW","payee_masked":"wx***23","failure_reason":null,"created_at":"2026-08-05T10:02:00","updated_at":"2026-08-05T10:02:00"}
```

**规则与错误**：创建时锁定账本，防止并发超额提现；`401`未登录，`409`余额不足或已有冲突申请，`422`金额不合法。

### 5. `POST /api/v1/admin/finance/commission-rules` 创建分成规则

**权限与请求信息**：仅超级管理员；JSON；成功 `201 Created`。

**请求参数**：`beneficiary_type` body 枚举 `service_matchmaker|store|promoter|partner`；`name` 1~128 字符；`mode` 枚举 `fixed|rate`；`fixed_amount` 固定金额规则必填、非负、2 位小数；`rate_percent` 比例规则必填、`0~100`、最多 4 位小数；`priority` 非负且不超过 `100000`，数值越大优先级越高。

**请求示例**：`{"beneficiary_type":"promoter","name":"推广分成","mode":"rate","rate_percent":"10.0000","priority":10}`。非法示例：`{"mode":"rate","rate_percent":"101"}`。

**返回参数与示例**：返回规则的 `id`、受益方、名称、模式、金额/比例、`priority`、`version`版本、`status`（`1`启用/`2`停用）、`created_at`。

```json
{"id":4,"beneficiary_type":"promoter","name":"推广分成","mode":"rate","fixed_amount":null,"rate_percent":"10.0000","priority":10,"version":1,"status":1,"created_at":"2026-08-05T10:03:00"}
```

**错误与规则**：固定模式缺少 `fixed_amount` 或比例模式缺少 `rate_percent` 返回 `422`；`401`未登录，`403`非管理员，`409`规则冲突。

### 6. `GET /api/v1/admin/finance/commission-rules` 查询分成规则

**权限与请求信息**：仅超级管理员；无请求体；成功 `200 OK`。

**请求参数**：无参数。请求示例：`GET /api/v1/admin/finance/commission-rules`。

**返回参数与示例**：返回规则数组，字段与创建规则接口完全相同；无规则返回 `[]`。

```json
[{"id":4,"beneficiary_type":"promoter","name":"推广分成","mode":"rate","fixed_amount":null,"rate_percent":"10.0000","priority":10,"version":1,"status":1,"created_at":"2026-08-05T10:03:00"}]
```

**错误**：`401`未登录，`403`非管理员，`503`数据库不可用。

### 7. `POST /api/v1/admin/finance/product-commission-rules/{product_id}` 配置商品分成

**请求参数**：path `product_id` 正整数；body `beneficiary_type` 为四种受益方枚举；`mode` 为 `fixed|rate`；`fixed_amount` 或 `rate_percent` 按模式必填，规则同创建分成规则。

**请求示例**：`POST /api/v1/admin/finance/product-commission-rules/9`，body `{"beneficiary_type":"service_matchmaker","mode":"rate","rate_percent":"30.0000"}`。非法示例：path 为 `0` 或模式与金额字段不匹配。

**返回参数与示例**：返回 `id`、`product_id`、受益方、模式、金额/比例、`version`、`status`、`created_at`。

```json
{"id":5,"product_id":9,"beneficiary_type":"service_matchmaker","mode":"rate","fixed_amount":null,"rate_percent":"30.0000","version":1,"status":1,"created_at":"2026-08-05T10:04:00"}
```

**规则与错误**：同商品同受益方新增版本会停用旧配置；`401`未登录，`403`非管理员，`404`商品不存在，`422`参数错误。

### 8. `POST /api/v1/admin/finance/orders/{order_id}/settle` 结算订单

**请求参数**：path `order_id` 正整数；无请求体。示例：`POST /api/v1/admin/finance/orders/101/settle`。

**返回参数与示例**：返回分成流水数组，每项包含 `id`、`order_id`、`beneficiary_type`、`beneficiary_id`、`base_amount`、`amount`、`status`、`created_at`。

```json
[{"id":8,"order_id":101,"beneficiary_type":"promoter","beneficiary_id":7,"base_amount":"99.00","amount":"9.90","status":"PENDING","created_at":"2026-08-05T10:05:00"}]
```

**规则与错误**：仅已支付订单可结算；生产环境不得用此沙箱接口确认支付；`403`非管理员，`404`订单不存在，`409`未支付/重复结算，`503`生产环境禁用。

### 9. `POST /api/v1/admin/finance/orders/{order_id}/refund` 退款并冲正

**请求参数**：path `order_id` 正整数；body `reason` 必填，1~255 字符，退款原因。

**请求示例**：`POST /api/v1/admin/finance/orders/101/refund`，body `{"reason":"用户取消服务"}`。非法示例：`{"reason":""}`。

**返回**：`204 No Content`，无返回体，不得尝试解析 JSON。

**规则与错误**：订单退款会冲正分成并关闭关联未完成业务；`403`非管理员，`404`订单不存在，`409`订单不可退款，`422`原因不合法。

### 10. `POST /api/v1/admin/finance/commission-entries/{entry_id}/release` 释放分成

**请求参数**：path `entry_id` 正整数；无请求体。示例：`POST /api/v1/admin/finance/commission-entries/8/release`。

**返回参数**：返回完整分成流水，字段为 `id`、`order_id`、`beneficiary_type`、`beneficiary_id`、`base_amount`、`amount`、`status`、`created_at`。成功示例：`{"id":8,"order_id":101,"beneficiary_type":"promoter","beneficiary_id":7,"base_amount":"99.00","amount":"9.90","status":"AVAILABLE","created_at":"2026-08-05T10:05:00"}`。

**规则与错误**：只允许 `PENDING -> AVAILABLE`；`403`非管理员，`404`流水不存在，`409`已释放或已冲正。

### 11. `PATCH /api/v1/admin/finance/withdrawals/{withdrawal_id}` 审核提现

**请求参数**：path `withdrawal_id` 正整数；body `status` 枚举 `APPROVED|REJECTED|PROCESSING|SUCCEEDED`；`failure_reason` 可选，最多 255 字符，拒绝/失败时应填写。

**请求示例**：`PATCH /api/v1/admin/finance/withdrawals/12`，body `{"status":"APPROVED","failure_reason":null}`。非法示例：`{"status":"PENDING_REVIEW"}`。

**返回参数与示例**：返回提现 `id`、账户、`amount`、新 `status`、脱敏收款方、`failure_reason`、创建和更新时间。

```json
{"id":12,"account_type":"user","account_id":23,"amount":"50.00","status":"APPROVED","payee_masked":"wx***23","failure_reason":null,"created_at":"2026-08-05T10:02:00","updated_at":"2026-08-05T10:06:00"}
```

**规则与错误**：状态按 `PENDING_REVIEW -> APPROVED -> PROCESSING -> SUCCEEDED` 流转；拒绝/失败写反向账本流水；`403`非管理员，`404`不存在，`409`非法状态流转，`422`参数错误。

### 12. `GET /api/v1/admin/finance/report` 查询财务报表

**请求参数**：无 query、path、body 参数；仅超级管理员。示例：`GET /api/v1/admin/finance/report`。

**返回参数与示例**：数组每项 `beneficiary_type` 受益方类型、`beneficiary_id` 受益方 ID、`order_count`订单数、`total_amount`总金额、`pending_amount`待结算金额、`available_amount`可用金额；无数据返回 `[]`。

```json
[{"beneficiary_type":"promoter","beneficiary_id":7,"order_count":3,"total_amount":"297.00","pending_amount":"9.90","available_amount":"19.80"}]
```

**错误**：`401`未登录，`403`非管理员，`503`数据库不可用。

## 二、约见

### 13. `POST /api/v1/matchmaker/meetings/requests` 提交约见申请

**权限与请求参数**：需登录、绑定手机号并通过实名认证；body `target_user_id` 正整数，约见对象；`note` 1~2000 字符，申请说明。

**请求示例**：`{"target_user_id":23,"note":"希望在门店进行首次沟通"}`。非法示例：`{"target_user_id":0,"note":""}`。

**返回参数与示例**：`id`申请 ID；`user_id`发起人；`target_user_id`目标用户；`service_id`服务单 ID，无则 `null`；`matchmaker_id`红娘 ID；`organization_id`组织 ID；`status`状态；`note`说明；`created_at`、`updated_at`。

```json
{"id":31,"user_id":23,"target_user_id":45,"service_id":null,"matchmaker_id":null,"organization_id":null,"status":"SUBMITTED","note":"希望在门店进行首次沟通","created_at":"2026-08-05T11:00:00","updated_at":"2026-08-05T11:00:00"}
```

**规则与错误**：本接口当前业务禁止普通用户直接发起，命中业务限制返回 `403/409`；`422`字段错误。

### 14. `POST /api/v1/matchmaker/meetings/requests/from-service` 红娘发起约见

**请求参数**：需认证服务红娘；`service_id` 正整数，已支付服务单；`target_user_id` 正整数，目标用户；`note` 1~2000 字符。

**请求示例**：`{"service_id":88,"target_user_id":45,"note":"根据服务安排进行首次见面"}`。

**返回**：返回字段与接口 13 相同；示例：`{"id":32,"user_id":23,"target_user_id":45,"service_id":88,"matchmaker_id":23,"organization_id":4,"status":"SUBMITTED","note":"根据服务安排进行首次见面","created_at":"2026-08-05T11:01:00","updated_at":"2026-08-05T11:01:00"}`。

**规则与错误**：服务必须为进行中或已完成，不能过期、退款、取消或由停用账号发起；`403`身份/归属不足，`404`服务单或目标不存在，`409`状态冲突，`422`参数错误。

### 15. `GET /api/v1/matchmaker/meetings/requests/mine` 查询我的约见申请

**请求参数**：无请求体和查询参数；需认证用户。示例：`GET /api/v1/matchmaker/meetings/requests/mine`。

**返回**：返回申请数组，每项字段同接口 13；无申请返回 `[]`。

**错误与规则**：只返回当前用户作为发起人或目标方的申请；`401`未登录，`403`未满足认证条件。

### 16. `PATCH /api/v1/matchmaker/meetings/requests/{request_id}` 处理约见申请

**请求参数**：path `request_id` 正整数；body `status` 枚举 `CONTACTED|ACCEPTED|DECLINED|CLOSED`；`reason` 可选且最多 255 字符，拒绝或关闭时必须填写。

**请求示例**：`PATCH /api/v1/matchmaker/meetings/requests/31`，body `{"status":"ACCEPTED","reason":null}`。非法示例：`{"status":"DECLINED"}`。

**返回**：完整 `MeetingRequestResponse`，字段同接口 13，`status`为更新后的状态。

**规则与错误**：只允许申请参与方处理；仅 `ACCEPTED` 可安排约会；`403`非参与方，`404`申请不存在，`409`非法状态流转，`422`原因缺失或格式错误。

### 17. `POST /api/v1/admin/matchmaker/meetings/requests/{request_id}/schedule` 安排约会

**请求参数**：仅超级管理员；path `request_id` 正整数；body `organizer_id` 正整数，组织者；`organization_id` 可选正整数；`scheduled_at` ISO 8601 时间；`location` 1~255 字符。

**请求示例**：`{"organizer_id":23,"organization_id":4,"scheduled_at":"2026-08-10T14:00:00+08:00","location":"上海直营店"}`。

**返回参数与示例**：`id`约会 ID；`request_id`申请 ID；`organizer_id`组织者；`organization_id`组织；`scheduled_at`安排时间；`location`地点；`status`（`SCHEDULED|REMINDED|CHECKED_IN|COMPLETED|CANCELLED|NO_SHOW`）；`cancel_reason`；`created_at`、`updated_at`。

```json
{"id":51,"request_id":31,"organizer_id":23,"organization_id":4,"scheduled_at":"2026-08-10T14:00:00+08:00","location":"上海直营店","status":"SCHEDULED","cancel_reason":null,"created_at":"2026-08-05T11:03:00","updated_at":"2026-08-05T11:03:00"}
```

**错误**：`403`非管理员，`404`申请不存在，`409`申请未接受或时间冲突，`422`时间/地点错误。

### 18. `POST /api/v1/matchmaker/meetings/{meeting_id}/feedback` 提交约见反馈

**请求参数**：path `meeting_id` 正整数；body `target_rating` 可选 `1~5`；`matchmaker_rating` 可选 `1~5`；`continue_intent` 可选枚举 `1|2|3`；`private_feedback` 可选，最多 2000 字符。

**请求示例**：`{"target_rating":5,"matchmaker_rating":4,"continue_intent":1,"private_feedback":"沟通顺利"}`。请求体 `{}` 合法，表示不填写评分。

**返回**：`204 No Content`，无返回体。

**规则与错误**：只有参与方且约会状态为 `CHECKED_IN` 或 `COMPLETED` 时可提交；`403`非参与方，`404`约会不存在，`409`状态不允许或重复提交，`422`评分越界。

## 三、会员、支付与积分

### 19. `GET /api/v1/membership/packages` 查询会员套餐

**请求参数**：无；公开接口。示例：`GET /api/v1/membership/packages`。

**返回参数与示例**：每项 `code`套餐编码；`name`名称；`duration_days`有效天数；`price`价格；`original_price`原价；`daily_price`日均价；`badge`标签；`rights`权益键值对象。

```json
[{"code":"monthly","name":"月度会员","duration_days":30,"price":99.0,"original_price":129.0,"daily_price":3.3,"badge":"推荐","rights":{"apply_daily":10,"browse_unlimited":true}}]
```

**空结果**：没有上架套餐返回 `[]`；价格以服务端配置为准，前端不得自行计算覆盖。

### 20. `GET /api/v1/users/me/membership` 查询会员状态

**请求参数**：无；需登录。示例：`GET /api/v1/users/me/membership`。

**返回参数**：`is_vip`是否有效会员；`package_type`套餐编码；`start_at`、`end_at`有效期；`rights`当前权益。

```json
{"is_vip":true,"package_type":"monthly","start_at":"2026-08-05T11:00:00","end_at":"2026-09-04T23:59:59","rights":{"apply_daily":10,"browse_unlimited":true}}
```

**无会员**：日期和套餐为 `null`，`is_vip=false`，`rights`返回当前普通用户权益。`401`未登录。

### 21. `GET /api/v1/users/me/membership/history` 查询会员历史

**请求参数**：query `page` 整数 `>=1`，默认 `1`；`page_size` `1~50`，默认 `20`。

**请求示例**：`GET /api/v1/users/me/membership/history?page=1&page_size=20`；非法示例 `page_size=0` 返回 `422`。

**返回参数与示例**：顶层 `items`历史数组、`page`、`page_size`、`total`、`has_more`；每项在会员状态字段外增加 `id`、`amount`、`order_no`、`status`订单状态。

```json
{"items":[{"id":6,"is_vip":true,"package_type":"monthly","start_at":"2026-08-05T11:00:00","end_at":"2026-09-04T23:59:59","rights":{"apply_daily":10},"amount":99.0,"order_no":"MO202608050001","status":1}],"page":1,"page_size":20,"total":1,"has_more":false}
```

**空结果**：`items: []`；`401`未登录，`422`分页错误。

### 22. `POST /api/v1/membership/orders` 创建会员订单

**请求参数**：body `package_code` 1~32 字符，必须是服务端返回的在售套餐编码；可选 Header `Idempotency-Key`，用于重复创建幂等。

### 59. `POST /api/v1/matchmaker/service-requests/{service_id}/contact-exchanges` 发起联系方式授权

**请求参数**：需登录且是服务申请参与方；path `service_id` 正整数；body `target_user_id` 正整数，待授权的另一方。

**请求示例**：`POST /api/v1/matchmaker/service-requests/88/contact-exchanges`，body `{"target_user_id":45}`；目标为本人或非服务参与方返回 `403/422`。

**返回参数与示例**：`id`授权交换 ID；`service_id`服务单；`source_user_id`发起方；`target_user_id`目标方；`status`（`PENDING|ONE_SIDE_CONSENT|APPROVED|DELIVERED|REVOKED|HIDDEN`）；双方同意时间；`delivered_at`、`hidden_at`、`hidden_reason`；`created_at`、`updated_at`。

{"id":17,"service_id":88,"source_user_id":23,"target_user_id":45,"status":"PENDING","source_consented_at":null,"target_consented_at":null,"delivered_at":null,"hidden_at":null,"hidden_reason":null,"created_at":"2026-08-05T13:01:00","updated_at":"2026-08-05T13:01:00"}

**规则与错误**：联系方式只在双方同意后交付；`401`未登录，`403`无服务权限，`404`服务不存在，`409`已有授权交换，`422`目标 ID 错误。

### 60. `PATCH /api/v1/matchmaker/service-requests/contact-exchanges/{exchange_id}` 同意/撤回授权

**请求参数**：需登录且为交换参与方；path `exchange_id` 正整数；body `action` 枚举 `CONSENT|REVOKE`。示例：`{"action":"CONSENT"}`；非法示例：`{"action":"APPROVE"}`。

**返回**：完整授权交换对象，字段同接口 59；双方同意后示例状态为 `APPROVED` 或 `DELIVERED`。

**规则与错误**：撤回会使未交付授权失效并隐藏联系方式；`403`非参与方，`404`交换不存在，`409`已交付后不能撤回，`422`动作错误。

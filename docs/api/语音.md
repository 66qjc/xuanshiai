# 语音接口（STT 语音转文字 / TTS 文字转语音）

接口前缀：`/api/v1`。本文件是 P-04 / Phase 4 语音能力对外的完整契约。语音能力属于 Phase 4，一期默认关闭（`ai_voice_enabled=false`、`ai_voice_provider=mock`）；生产启用需满足三道审批门禁且 provider 不为 mock，还须完成阿里云 DPA / 数据出境审查。

### 变更记录

- 2026-08-31：墨相师画像建构 WebSocket 增加双主体阶段切换：新增上行 `subject_switch`、下行 `subject_changed`，`progress` / `confirm_card` / `publish_ready` 增加 `subject`；personal 与 ideal_partner 分别维护 master 会话、草稿、进度与发布状态。
- 2026-08-23：实时对话 WebSocket 增加 `ai_reasoning` / `ai_content` 增量帧，以及上行 `revise_text` / `listen`。`audio_end` 只推转写与回复文本，不再自动推 `tts_audio`；确认前静音，客户端点「听它读」才合成。实时 WS 仍不写画像。
- 2026-08-20：新增 2 个 `/api/v1/voice/*` 路径（STT 异步转写 + TTS 同步合成）；错误统一为 `AiErrorDetail` 形状（含 `request_id`）；普通响应不携带音频原文、provider trace 或密钥。

通用请求头（所有接口）：

```http
Authorization: Bearer <access_token>   # 必需
Idempotency-Key: <8-128 位 ASCII>       # 所有写接口必需；重复 key + 相同请求摘要回放第一次结果
```

通用说明：

- 前置条件：已登录；手机号已验证。
- 语音功能门禁：`ai_voice_enabled=true` 且生产环境满足三道审批门禁（`ai_policy_approved` + `ai_provider_approved` + `ai_retention_policy_version`）。
- 开发/测试环境可用 mock provider；生产环境禁止使用 mock Voice Provider（`_validate_ai_feature_gates` 强制 fail-closed）。
- 错误响应统一为：

```json
{
  "detail": {
    "code": "AI_FEATURE_DISABLED",
    "message": "语音功能当前不可用",
    "request_id": "req_01JXc5...",
    "retryable": false,
    "retry_after_ms": 0
  }
}
```

## §1 语音转写（STT）—— 上传音频异步转写

### 请求

```http
POST /api/v1/voice/transcribe
Content-Type: multipart/form-data
Authorization: Bearer <access_token>
Idempotency-Key: portrait-1234567890-abc

audio: <binary file, mp3/wav/m4a, ≤5MB, ≤60s, 16kHz 单声道>
question_field_key: age
```

### 请求参数

| 参数 | 位置 | 类型 | 必需 | 约束 | 说明 |
|---|---|---|---|---|---|
| `audio` | form file | binary | 是 | mp3/wav/m4a, ≤5MB | 音频文件（前端 `VoiceRecorder` 录制参数：mp3/16kHz/单声道/≤60s）|
| `question_field_key` | form field | string | 是 | ≤64 字符 | 画像字段 key（如 `age`/`city_code`），用于 mock fixture 匹配 |
| `Idempotency-Key` | header | string | 是 | 8-128 位 ASCII | 幂等键 |

### 成功响应（202 Accepted）

```json
{
  "task_id": "a1b2c3d4e5f6...",
  "status": "queued",
  "poll_after_ms": 1000
}
```

### 轮询结果

通过 `GET /api/v1/ai/tasks/{task_id}` 轮询任务状态（复用 AI 通用任务接口）。当 `status=succeeded` 时，响应中 `result_payload.transcript` 为转写文本：

```json
{
  "task_id": "a1b2c3d4e5f6...",
  "status": "succeeded",
  "poll_after_ms": 0,
  "result_ref": "a1b2c3d4e5f6...",
  "result_payload": {
    "transcript": "我今年28岁，从事产品设计工作"
  },
  "error_code": null,
  "error_message": null
}
```

### 错误码

| HTTP | code | 说明 | retryable |
|---|---|---|---|
| 400 | `AI_INPUT_INVALID` | Idempotency-Key 格式错误或音频为空 | false |
| 403 | — | 未登录或手机号未验证 | false |
| 413 | `AI_INPUT_INVALID` | 音频文件超过 5MB | false |
| 422 | `AI_INPUT_INVALID` | 音频内容为空 | false |
| 503 | `AI_FEATURE_DISABLED` | 语音功能未启用 | false |
| 409 | `TASK_IDEMPOTENCY_CONFLICT` | 同 key 不同请求摘要 | false |

## §2 语音合成（TTS）—— 文本转语音同步返回

### 请求

```http
POST /api/v1/voice/synthesize
Content-Type: application/json
Authorization: Bearer <access_token>
Idempotency-Key: portrait-1234567890-abc

{
  "text": "请告诉我你的年龄",
  "locale": "zh-CN"
}
```

### 请求参数

| 参数 | 位置 | 类型 | 必需 | 约束 | 说明 |
|---|---|---|---|---|---|
| `text` | body | string | 是 | 1-500 字符 | 待合成的问题文本 |
| `locale` | body | string | 否 | — | 语言代码（如 `zh-CN`）|
| `voice` | body | string | 否 | 默认 `default` | 发音人音色 |
| `speed` | body | number | 否 | 0.5-2.0，默认 1.0 | 语速 |
| `Idempotency-Key` | header | string | 是 | 8-128 位 ASCII | 幂等键 |

### 成功响应（200 OK）

```json
{
  "audio_url": "https://xhztest.xyz/storage/voice/tts/abc123.mp3",
  "audio_format": "mp3",
  "duration_ms": 3000,
  "expires_at": null
}
```

前端通过 `uni.createInnerAudioContext()` 设置 `src = audio_url` 后 `play()` 播放。

### 错误码

| HTTP | code | 说明 | retryable |
|---|---|---|---|
| 400 | `AI_INPUT_INVALID` | Idempotency-Key 格式错误或文本为空/超长 | false |
| 403 | — | 未登录或手机号未验证 | false |
| 503 | `AI_FEATURE_DISABLED` | 语音功能未启用 | false |
| 503 | `AI_TEMPORARILY_UNAVAILABLE` | 语音服务暂时不可用 | true |
| 503 | `AI_QUOTA_EXCEEDED` | 语音服务请求频率过高 | true |

| code | HTTP | retryable | 说明 |
|---|---|---|---|
| `AI_FEATURE_DISABLED` | 503 | false | 语音功能未启用或审批门禁未通过 |

| `TASK_IDEMPOTENCY_CONFLICT` | 409 | false | 幂等键已用于不同请求内容 |

## §4 实时半双工语音对话（WebSocket）

#### 实时对话

**基本信息**：墨相「和 AI 对话」沉浸层的半双工实时通道。客户端点麦说话，服务端推 ASR 字幕、流式回复文本；确认前不写画像、不自动外放。完整 URL `ws(s)://<host>/api/v1/voice/conversation?token=<access_token>`，Method WebSocket，需要登录，角色为已登录用户，Content-Type 为 JSON 文本帧，成功时连接保持到客户端断开。生产环境 `ai_voice_conversation_enabled` 默认关闭，未开门禁时握手失败（close 1008）。

**请求参数**：

| 参数 | 位置 | 类型 | 必填 | 默认值 | 校验 | 业务含义 |
|---|---|---|---|---|---|---|
| `token` | query | string | 是 | 无 | 有效 JWT access token | WS 不走 HTTP 中间件，用 query 鉴权。非法示例：缺 token、过期 token |
| `type` | body | string | 是 | 无 | 见上行枚举 | 消息种类 |
| `session_id` | body | string | `session_start` 时是 | 无 | 非空会话 id | 本轮对话会话 |
| `field_key` | body | string | 否 | `""` | 画像字段 key | 当前想了解的方面 |
| `data` | body | string | `audio_chunk` 时是 | 无 | base64 PCM | 音频块，不入审计日志 |
| `seq` | body | int | 否 | 无 | 递增序号 | 音频块顺序 |
| `text` | body | string | `revise_text` 时是 | 无 | trim 后非空 | 用户改写后的转写；空串返回 `AI_INPUT_INVALID` |

上行 `type` 枚举：`session_start`、`audio_start`、`audio_chunk`、`audio_end`、`revise_text`、`listen`、`cancel`。

**请求体示例**：

```json
{"type": "session_start", "session_id": "sess1", "field_key": "age"}
{"type": "audio_start"}
{"type": "audio_chunk", "data": "<base64 PCM>", "seq": 1}
{"type": "audio_end"}
{"type": "revise_text", "text": "我住杭州"}
{"type": "listen"}
{"type": "cancel"}
```

非法示例：`{"type": "revise_text", "text": "   "}` → `error.code=AI_INPUT_INVALID`。

**返回参数**：

| 字段 | 类型 | 必返 | 空值含义 | 业务含义 | 示例 |
|---|---|---|---|---|---|
| `type` | string | 是 | 无 | 下行种类 | `ai_content` |
| `text` | string | 字幕/回复帧是 | 空串表示本片无字 | ASR 或模型增量 | `记下了` |
| `field_key` | string | `ai_reply` 是 | 回落到 session 的 field_key | 本轮关注字段 | `age` |
| `audio_url` | string | `tts_audio` 是 | 无此帧 | 仅 `listen` 之后出现 | `/tts/test.mp3` |
| `duration_ms` | int | `tts_audio` 是 | `0` 表示未知 | 音频时长 | `2000` |
| `code` | string | `error` 是 | 无 | 稳定错误码 | `AI_INPUT_INVALID` |
| `message` | string | `error` 是 | 无 | 可展示说明 | `改写文本为空` |

下行 `type` 枚举：`partial_transcript`、`final_transcript`、`ai_thinking`、`ai_reasoning`、`ai_content`、`ai_reply`、`tts_audio`、`error`。

**返回示例**：

`audio_end` 之后（无 `tts_audio`）：

```json
{"type": "final_transcript", "text": "我今年28岁，在北京工作"}
{"type": "ai_thinking"}
{"type": "ai_reasoning", "text": "先接住年龄"}
{"type": "ai_content", "text": "记下了，你在哪座城市？"}
{"type": "ai_reply", "text": "记下了，你在哪座城市？", "field_key": "age"}
```

客户端再发 `listen` 后：

```json
{"type": "tts_audio", "audio_url": "/storage/voice/tts/abc.mp3", "duration_ms": 2000}
```

**使用方法与业务规则**：

- 前置：已登录；`ai_voice_enabled` 与 `ai_voice_conversation_enabled` 均为 true。生产默认关闭。
- 调用顺序：`session_start` → `audio_start` → 若干 `audio_chunk` → `audio_end`。之后可 `revise_text` 重跑回复，或 `listen` 合成当前回复。
- 实时 WS **不写画像**。抽取结果只留在编排器内存；写入必须由父页确认后走 `submitAnswer`。
- `audio_end` 不再自动 TTS。确认前可以流式生成回复文本，不自动外放。
- `revise_text` 会 bump generation，丢弃旧流，按新文本重跑；不要把新旧回复叠在同一张纸上。
- `cancel` 先 bump generation 再 reset，丢弃在途生成与上一轮回复缓存。
- 幂等：WS 帧不走 HTTP Idempotency-Key。
- 前端：有完整 `ai_reply` 后再提供「听它读」；改字失焦或停顿后发 `revise_text`。

**错误**：

| 场景 | 通道 | code | 前端处理 |
|---|---|---|---|
| 门禁关闭 / 生产未开 | 握手 close 1008 | `AI_FEATURE_DISABLED` | 隐藏实时对话入口 |
| 缺 token / 无效 token | 握手 close 1008 | — | 重新登录 |
| `revise_text` 空串 / 未 session_start | 下行 `error` | `AI_INPUT_INVALID` | 提示改写后再试 |
| ASR / TTS / 模型暂时失败 | 下行 `error` | `AI_TEMPORARILY_UNAVAILABLE` / `AI_QUOTA_EXCEEDED` | 可重试或改打字 |

## §5 墨相师双画像建构（WebSocket）

#### 双主体连续建构

**基本信息**：墨相师的正式画像建构通道。完整 URL `ws(s)://<host>/api/v1/voice/moxiang-master?token=<access_token>`，Method WebSocket，需要登录，Content-Type 为 JSON 文本帧。`session_start.mode=profile_build` 时写入画像；不带 `mode` 时保持纯聊天兼容，不创建画像会话。

一个连接保留同一条聊天时间线，但画像数据按两个主体隔离：

- `personal`：我的墨相，只写用户自己的性格、恋爱观、关系边界和生活方式。
- `ideal_partner`：愿遇之相，只写用户明确表达并确认的择偶偏好、理想人格与相处期待。

**鉴权与授权**：

| 参数 | 位置 | 类型 | 必填 | 默认值 | 校验 | 业务含义 |
|---|---|---|---|---|---|---|
| `token` | query | string | 是 | 无 | 有效 JWT access token | 缺失或无效时 close 1008 |
| `type` | body | string | 是 | 无 | 上行类型枚举 | 消息种类 |
| `mode` | body | string | 否 | 纯聊天 | `profile_build`（画像建构） | 只在 `session_start` 使用 |
| `subject` | body | string | 建构开始/切换时是 | `personal` | `personal` / `ideal_partner` | 当前画像主体 |
| `consentVersion` | body | string | 建构开始时是 | `profile-text-v1` | 有效授权版本 | 复用 `profile_text_extract` 授权 |
| `text` | body | string | `text_message` 时是 | 无 | trim 后 1—2000 字 | 用户本轮原文 |
| `clientTurnId` | body | string | 否 | 服务端生成 | 客户端轮次幂等标识 | 便于重放与对账 |
| `data` | body | string | `audio_chunk` 时是 | 无 | base64 PCM，单片不超过服务端限制 | 音频块 |
| `seq` | body | int | 否 | 无 | 递增序号 | 音频块顺序 |

上行 `type` 枚举：`session_start`、`subject_switch`、`text_message`、`audio_start`、`audio_chunk`、`audio_end`、`listen`、`revise_text`、`cancel`。

**开始与切换示例**：

```json
{
  "type": "session_start",
  "mode": "profile_build",
  "subject": "personal",
  "consentVersion": "profile-text-v1"
}
```

```json
{
  "type": "subject_switch",
  "subject": "ideal_partner"
}
```

切换成功按顺序返回主体确认、目标主体进度、可能存在的待确认卡片或发布就绪状态，以及该阶段开场白：

```json
{"type": "subject_changed", "subject": "ideal_partner"}
{"type": "progress", "subject": "ideal_partner", "percent": 60, "hard_done": 2, "hard_total": 3, "entry_score": 1, "gate_met": false}
{"type": "ai_reply", "text": "接下来我们聊聊你期待遇见怎样的人……"}
```

**建构下行参数**：

| 字段 | 类型 | 必返 | 空值含义 | 业务含义 | 示例 |
|---|---|---|---|---|---|
| `type` | string | 是 | 无 | 下行消息类型 | `progress` |
| `subject` | string | 主体消息是 | 无 | 消息所属画像主体，不等同于当前 UI 主体 | `ideal_partner` |
| `percent` | number | `progress` 是 | `0` 为尚无已确认内容 | 当前主体建构进度 | `60` |
| `hard_done` | int | `progress` 是 | `0` 为尚未确认硬字段 | 已确认硬字段数 | `2` |
| `hard_total` | int | `progress` 是 | 无 | 硬字段总数 | `3` |
| `entry_score` | number | `progress` 是 | `0` 为无已确认条目计分 | 当前主体条目折算分 | `1` |
| `gate_met` | boolean | `progress` 是 | `false` 未达门槛 | 当前主体是否可发布 | `false` |
| `card_id` | string | `confirm_card` 是 | 无 | 前端卡片展示标识 | `c-...` |
| `draft_id` | string | `confirm_card` 是 | 无 | REST 草稿确认接口使用 | `d-...` |
| `expected_revision` | int | `confirm_card` 是 | `0` 为初始版本 | 乐观锁版本，必须使用卡片自身值 | `3` |
| `items` | array | `confirm_card` 是 | 空卡片不发送 | 待确认字段/条目 | `[]` |
| `summary` | string | `publish_ready` 是 | 无 | 当前主体成稿引导 | `你的个人画像已经可以成稿了` |

**完整建构消息示例**：

```json
{
  "type": "confirm_card",
  "subject": "ideal_partner",
  "card_id": "c-01",
  "draft_id": "d-01",
  "expected_revision": 3,
  "items": [
    {
      "field_key": "entry:personality:01",
      "kind": "entry",
      "category": "personality",
      "content": "希望未来伴侣温柔、稳定",
      "display_value": "希望未来伴侣温柔、稳定",
      "value": null
    }
  ]
}
```

```json
{
  "type": "publish_ready",
  "subject": "personal",
  "summary": "你的个人画像已经可以成稿了"
}
```

**主体与会话规则**：

- 每个主体各维护一个 `session_kind=master` 的活动会话。切换不会删除、暂停或重置另一主体。
- `text_message` / `audio_end` 开始处理时锁定当时主体，该轮落库、回复保存和抽取轮询始终使用同一个 session。
- 非当前主体的后台抽取可以继续完成；其 `progress`、`confirm_card`、`publish_ready` 仍携带原主体，客户端应缓存而非错误渲染到当前主体。
- WebSocket 重连后客户端用最后主体重放 `session_start`；另一个主体在切回时按用户+主体复用原 master 会话并恢复进度/卡片。
- 同主体存在旧 `build` / `update` 活动会话时，不把它当作 master 复用：旧会话保留并标记 `stale`、释放活动槽，再创建 master 会话；不物理删除旧草稿和轮次。
- 两个主体分别确认、分别发布和生成 narrative；一方成功不自动推进另一方。

**具体对象与抽取边界**：

- 「他很温柔」是对现实具体对象的观察，只用于帮助用户理解自己的感受，抽取器返回空 `patches`。
- 「我希望未来伴侣温柔、稳定」属于明确偏好，可以形成 ideal_partner 候选，但仍需用户通过确认卡片确认。
- 混合表达由墨相师追问主体含义；抽取器不生成 `clarifying_question`，也不创建第三方画像。
- personal 与 ideal_partner 的 provider 输出主体必须与 session 主体一致，否则按现有画像校验拒绝落库。

**错误与前端处理**：

| 场景 | code / close | retryable | 前端处理 |
|---|---|---|---|
| 缺 token / token 无效 | close 1008 | false | 重新登录 |
| 非法 subject、空文本、过长消息 | `AI_INPUT_INVALID` | false | 保持当前主体，修正输入 |
| 缺少 `profile_text_extract` 授权 | `AI_CONSENT_REQUIRED` | false | 只提示目标主体授权问题，不破坏已建立主体 |
| DB / Provider / ASR 暂时失败 | `AI_TEMPORARILY_UNAVAILABLE` | true | 保持当前主体，可重试或主动进入备用题库/语音流程 |
| 语音门禁关闭 | `AI_FEATURE_DISABLED` | false | 继续使用文字建构 |

切换只有在目标 master 会话与上下文加载成功后才生效；失败时服务端不发送 `subject_changed`，客户端不得提前改变当前主体。

# 客源线索接口

## 通用约定

所有接口前缀为 `/api/v1`，需要 `Authorization: Bearer <access-token>`，且后台账号必须具有 `customer_lead.manage` 或 `*` 权限。所有写入均记录操作者审计日志；不返回密码、令牌或未脱敏支付信息。

## `GET /admin/customer-leads`

**基本信息**：分页查询客源线索；成功状态 `200`；无请求体。

**请求参数**：`page`（query，默认 `1`，范围 `1..1000`）、`page_size`（默认 `20`，范围 `1..100`）、`status`（可选：`NEW/CONTACTED/INTENDED/CONVERTED/LOST/CLOSED`）、`source`（可选，最长 64 字符）、`matchmaker_id`（可选正整数）和 `search`（可选，最长 64 字符，按称呼、手机、微信模糊匹配）。非法示例：`page_size=101` 返回 `422`。

**请求示例**：`GET /api/v1/admin/customer-leads?page=1&page_size=20&status=NEW&search=张`，Header 为 `Authorization: Bearer <access-token>`；无请求体。

**返回参数**：`items[]` 每项包含 `id/name/phone/wechat/source/intention_level/status/matchmaker_id/organization_id/next_follow_at/converted_user_id/remark/created_by/created_at/updated_at`；`intention_level` 为 `1` 低、`2` 中、`3` 高；分页包含 `page/page_size/total/has_more`。空数据响应为 `{"items":[],"page":1,"page_size":20,"total":0,"has_more":false}`。

**使用方法与业务规则**：只读、可分页筛选；记录创建、分派、修改和跟进必须调用对应写接口。无数据不是错误。

**错误**：`401` 未登录；`403` 无客源管理权限；`422` 参数非法；`500` 查询失败。

## 写接口

`POST /admin/customer-leads` 创建线索，要求 `name/source` 与至少一个 `phone/wechat`；`PATCH /admin/customer-leads/{lead_id}` 修改基础字段；`PATCH /admin/customer-leads/{lead_id}/assignment` 分派有效服务红娘或启用门店；`POST /admin/customer-leads/{lead_id}/follow-ups` 写入跟进，要求 `method` 为 `PHONE/WECHAT/VISIT/OTHER`、`content` 长度 `1..2000`。这些接口均需相同权限、均有参数校验和审计日志。

**变更记录（2026-08-17）**：客源线索所有路由统一增加 `customer_lead.manage` 权限校验；旧的管理员通配权限 `*` 继续兼容。

## 弃海闭环（新增，2026-08-17）

### `POST /admin/customer-leads/{lead_id}/abandon`

**用途**：将未入库、未关闭的客源安全放入弃海池。需登录和 `customer_lead.manage` 权限；`lead_id` 为正整数 path 参数，Body 为 `{"reason":"连续多次联系未回复"}`，`reason` 必填，长度 `1..500`。成功 `201`，返回 `id/lead_id/reason/abandoned_by/abandoned_at/restored_by/restored_at/restore_reason`；未恢复记录中的后三项为 `null`。

操作会将线索状态改为 `LOST`、清空服务红娘和下次跟进时间，并写入业务审计日志，不删除原线索、跟进或历史记录。已入库、已关闭或已在弃海池返回 `409`；无权限 `403`；不存在 `404`；参数非法 `422`。前端在成功后重新加载线索列表和弃海池，不应本地隐藏记录。

### `POST /admin/customer-leads/{lead_id}/restore`

**用途**：从弃海池恢复客源。权限和参数同弃海接口，Body 为 `{"reason":"客户重新主动联系"}`。成功 `200`，返回恢复后的完整客源对象；会保留弃海历史，写入恢复人、恢复时间、恢复原因，并把线索状态恢复为 `NEW`。非弃海客源返回 `409`。

### `GET /admin/customer-leads/abandoned` 与 `GET /admin/customer-leads/abandonments`

**用途**：前者查询当前仍在弃海池的记录，后者查询全部弃海和恢复历史。无请求体、无 query 参数，成功 `200` 返回上述弃海记录数组；空数组合法。均需要登录及 `customer_lead.manage`。当前版本按记录倒序返回，下一版本会增加与主列表一致的分页、关键词和数据范围过滤；前端应把返回当作只读审计数据，恢复必须调用恢复接口。

**兼容性**：全部为新增 URL，不修改原客源列表、详情、分派和跟进契约。

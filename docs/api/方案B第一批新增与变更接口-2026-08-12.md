# 方案 B 第一批新增与变更接口

生成日期：2026-08-12  
适用代码基线：`main@8d0c3d5` 加本次工作区修改  
认证说明：除特别注明外，C 端接口使用普通用户 Bearer Token；红娘后台接口使用独立红娘后台 Bearer Token。

> 本文记录本轮实际落地的接口增量。产品架构仍以 XMind 和 2026-08-05 例会文档为准，四份 Markdown 接口清单只作补充。

## 1. 红娘申请审核工作台

### 1.1 分页查询红娘申请

**基本信息**：后台分页检索红娘/合伙人申请。URL `GET /api/v1/admin/matchmaker/applications`；需要红娘后台登录；权限 `matchmaker.application.read`；成功状态码 200。

**请求参数**：

| 参数 | 位置 | 类型 | 必填 | 默认值 | 校验与含义 |
| --- | --- | --- | --- | --- | --- |
| page | query | integer | 否 | 1 | 大于等于 1 |
| page_size | query | integer | 否 | 20 | 1-100 |
| application_type | query | string | 否 | null | 最大 32 字符，申请类型筛选 |
| status | query | integer | 否 | null | 0-3，申请状态筛选 |
| search | query | string | 否 | null | 最大 128 字符，按姓名或手机号模糊搜索 |

**请求体示例**：无请求体。

`GET /api/v1/admin/matchmaker/applications?page=1&page_size=20&status=0&search=138`

非法示例：`page_size=101` 返回 422。

**返回参数**：`items` 为申请数组；每项包含 `id/application_type/status/real_name/phone_masked/intro/cert_images/application_details/fail_reason/created_at/reviewed_at`；分页字段为 `page/page_size/total/has_more`。`application_details` 包含微信、头像、擅长领域、期望价格和成功案例等审核资料，联系方式按现有响应转换规则脱敏。

**返回示例**：

```json
{
  "items": [{
    "id": 12,
    "application_type": "service_matchmaker",
    "status": 0,
    "real_name": "张某",
    "phone_masked": "138****8000",
    "intro": "申请说明",
    "cert_images": [],
    "application_details": {
      "wechat": null,
      "avatar": null,
      "specialties": ["同城婚恋"],
      "expected_price": 199.0,
      "success_cases": []
    },
    "fail_reason": null,
    "created_at": "2026-08-12T08:00:00",
    "reviewed_at": null
  }],
  "page": 1,
  "page_size": 20,
  "total": 1,
  "has_more": false
}
```

**使用方法与业务规则**：列表按创建时间、ID 倒序；搜索同时匹配真实姓名和手机号；前端不得把审核详情直接作为公开红娘主页数据。

**错误**：401 Token 无效；403 缺少读取权限；422 参数校验失败。

### 1.2 查询红娘申请详情

**基本信息**：URL `GET /api/v1/admin/matchmaker/applications/{application_id}`；权限 `matchmaker.application.read`；成功状态码 200。

**请求参数**：`application_id` 位于 path，integer，必填，大于等于 1。无请求体。

**返回参数与示例**：返回单个申请对象，字段同 1.1 的 `items[]`。

**使用方法与业务规则**：仅供审核工作台使用，不代表公开资料已发布。

**错误**：401 未登录；403 权限不足；404 申请不存在；422 路径参数非法。

### 1.3 审核红娘申请

**基本信息**：URL `PATCH /api/v1/admin/matchmaker/applications/{application_id}`；权限 `matchmaker.application.review`；Content-Type `application/json`；成功状态码 200。

**请求参数**：

| 参数 | 位置 | 类型 | 必填 | 规则与含义 |
| --- | --- | --- | --- | --- |
| application_id | path | integer | 是 | 大于等于 1 |
| status | body | integer | 是 | 1 通过、2 驳回、3 暂停 |
| fail_reason | body | string/null | 条件必填 | 驳回或暂停时必填，最大 255 字符 |

**请求体示例**：

```json
{"status": 2, "fail_reason": "证明材料不完整"}
```

非法示例：`{"status": 2}` 返回 422。

**返回参数**：返回审核后的完整申请对象。

**使用方法与业务规则**：审核动作写入现有审核记录并生成站内通知；通过时沿用现有角色授予流程。公开主页、案例发布和评价治理不在本接口中自动完成。

**错误**：401 未登录；403 缺少审核权限；404 申请不存在；409 状态冲突按现有审核服务返回；422 请求体非法。

## 2. 聊天会话管理

### 2.1 游标分页查询聊天记录

**基本信息**：URL `GET /api/v1/chat/sessions/{session_id}/messages/cursor`；普通用户登录；成功状态码 200。

**请求参数**：`session_id` 为大于等于 1 的路径参数；`cursor` 为可选消息 ID，大于等于 1；`page_size` 默认 20，范围 1-50。无请求体。

**返回参数**：`items` 为按时间正序排列的本页消息；消息字段为 `id/session_id/from_user_id/to_user_id/type/content/media_url/is_read/revoked/is_recalled/recalled_at/created_at`；`next_cursor` 为空表示无下一页；`has_more` 表示是否还有更早消息。

**返回示例**：

```json
{
  "items": [{
    "id": 101,
    "session_id": 8,
    "from_user_id": 1,
    "to_user_id": 2,
    "type": 1,
    "content": "你好",
    "media_url": null,
    "is_read": false,
    "revoked": false,
    "is_recalled": false,
    "recalled_at": null,
    "created_at": "2026-08-12T09:00:00"
  }],
  "next_cursor": 101,
  "has_more": true
}
```

**使用方法与业务规则**：首次不传 `cursor`；加载更早消息时传上次响应的 `next_cursor`。旧页码接口继续保留，前端迁移期间不得混用两种分页游标。

**错误**：401 未登录；403/404 无权访问或会话不存在；422 参数非法。

### 2.2 置顶与取消置顶会话

**基本信息**：置顶 `PUT /api/v1/chat/sessions/{session_id}/pin`；取消置顶 `DELETE /api/v1/chat/sessions/{session_id}/pin`；成功状态码 204；无请求体、无返回体。

**请求参数**：`session_id` 为大于等于 1 的路径参数。

**使用方法与业务规则**：置顶状态按用户独立保存，不影响对方；会话列表优先显示当前用户置顶会话，再按置顶时间或最后消息时间排序。

**错误**：401 未登录；403/404 无权访问或会话不存在；422 参数非法。

### 2.3 隐藏与恢复会话

**基本信息**：隐藏 `DELETE /api/v1/chat/sessions/{session_id}`；恢复 `POST /api/v1/chat/sessions/{session_id}/restore`；成功状态码 204；无请求体、无返回体。

**使用方法与业务规则**：DELETE 是当前用户单侧隐藏，不物理删除会话和消息，不影响对方。对方发送新消息时，接收方已隐藏的会话会自动恢复。证据保全或后台取证能力尚未完成，前端不得描述为“永久删除”。

**错误**：401 未登录；403/404 无权访问或会话不存在；422 参数非法。

## 3. 会话结构化请求

### 3.1 发起请求

**基本信息**：URL `POST /api/v1/chat/sessions/{session_id}/requests`；普通用户登录；Content-Type `application/json`；成功状态码 201。

**请求参数**：

| 参数 | 位置 | 类型 | 必填 | 规则与含义 |
| --- | --- | --- | --- | --- |
| session_id | path | integer | 是 | 大于等于 1 |
| request_type | body | enum | 是 | `ANSWER_EXCHANGE/LOVE_MODE/WECHAT/PHONE` |
| payload | body | object/null | 否 | 请求附加数据，内部结构由具体业务约定 |
| expire_hours | body | integer | 否 | 默认 48，范围 1-168 |

**请求体示例**：

```json
{"request_type": "WECHAT", "payload": {"message": "方便交换微信吗"}, "expire_hours": 48}
```

非法示例：`{"request_type":"UNKNOWN"}` 返回 422。

**返回参数**：`id/session_id/requester_id/responder_id/request_type/payload/status/expire_at/responded_at/created_at`。初始状态为 `PENDING`。

**使用方法与业务规则**：同一会话、同一发起人、同一类型在未过期的 PENDING 状态下只能有一条；该接口只记录双方意愿，不自动返回微信或电话明文。联系方式实际暴露仍受现有付费/授权逻辑和待确认产品口径约束。

**错误**：401 未登录；403/404 会话不可访问；409 同类型请求待处理；422 参数非法。

### 3.2 查询请求列表

**基本信息**：URL `GET /api/v1/chat/sessions/{session_id}/requests`；成功状态码 200；无请求体。

**返回参数**：返回结构化请求数组，字段同 3.1；按 ID 倒序。

**使用方法与业务规则**：仅会话双方可查询；服务会把已到期但仍为 PENDING 的记录更新为 `EXPIRED` 后返回。

**错误**：401 未登录；403/404 会话不可访问；422 参数非法。

### 3.3 处理或撤回请求

**基本信息**：URL `PATCH /api/v1/chat/session-requests/{request_id}`；Content-Type `application/json`；成功状态码 200。

**请求参数**：`request_id` 为大于等于 1 的路径参数；body 的 `action` 为 `ACCEPT/REJECT/WITHDRAW`。

**请求体示例**：`{"action":"ACCEPT"}`。

**返回参数**：返回更新后的结构化请求。

**使用方法与业务规则**：只有接收人可以接受或拒绝，只有发起人可以撤回；已处理或已过期请求不可再次操作。状态分别流转为 `ACCEPTED/REJECTED/WITHDRAWN/EXPIRED`。

**错误**：401 未登录；403 操作人角色不符；404 请求不存在；409 已处理或过期；422 参数非法。

## 4. 分类未读与通知筛选

### 4.1 查询分类未读汇总

**基本信息**：URL `GET /api/v1/notifications/unread-summary`；普通用户登录；成功状态码 200；无请求体。

**返回参数**：`total` 为全部未读数；`categories` 为按 `notification_type` 聚合的键值对象。

**返回示例**：

```json
{"total": 5, "categories": {"matchmaker_application_reviewed": 1, "chat_request": 4}}
```

**使用方法与业务规则**：分类键来自通知数据中的 `notification_type`，前端应为未知分类提供兜底展示。

**错误**：401 未登录。

### 4.2 按通知类型筛选通知列表

**基本信息**：变更接口 `GET /api/v1/notifications`；新增可选 query 参数 `notification_type`，最大 64 字符；其余分页参数与原接口一致。

**使用方法与业务规则**：不传时返回全部通知；传入时只返回对应分类，并同步计算该筛选范围内的未读数。公告和微信订阅消息能力尚未落地。

**错误**：401 未登录；422 参数非法。

## 5. 红娘后台账号数据范围与权限变更

### 5.1 账号字段变更

账号创建、详情、列表和更新接口增加：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| data_scope | enum | `SELF/STORE/ORGANIZATION/ALL`，默认 `SELF` |
| organization_id | integer/null | 组织 ID，可显式清空 |

更新账号时，显式传 `matchmaker_user_id: null` 可解除红娘用户绑定；显式传 `organization_id: null` 可清空组织绑定。该字段契约已持久化，但全业务查询 SQL 的组织范围过滤尚未完成，不能把字段存在等同于数据隔离已经验收。

### 5.2 权限要求

| 接口类别 | 权限 |
| --- | --- |
| 红娘申请列表/详情 | `matchmaker.application.read` |
| 红娘申请审核 | `matchmaker.application.review` |
| 后台账号管理 | `matchmaker.account.manage` |
| 财务查询 | `finance.read` |
| 财务写操作 | `finance.write` |
| 约见查询 | `meeting.read` |
| 约见安排/更新 | `meeting.write` |
| 约见反馈查询 | `meeting.feedback.read` |

升级初始化只为数据库中 ID 最小的首个红娘后台账号补 `*` 超级权限；无权限记录不再隐式等同于超级管理员。`GET /api/v1/admin/matchmaker/auth/me` 返回数据库中的真实权限列表。

### 5.3 约见安排前置条件

`POST /api/v1/admin/matchmaker/meetings/requests/{request_id}/schedule` 现在使用独立红娘后台身份，并要求后台账号已绑定 `matchmaker_user_id`。未绑定时返回 409：

```json
{"detail":"当前后台账号未绑定红娘用户，不能安排约见"}
```

## 6. 数据库结构

新增表 `chat_session_request`，保存会话结构化请求。兼容迁移为 `chat_session` 增加 `user1_pinned_at/user2_pinned_at`，为 `matchmaker_admin_account` 增加 `data_scope/organization_id`。生产环境必须通过正式迁移与回滚流程执行，不得依赖应用启动自动改表。

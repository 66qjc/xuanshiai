# 管理端首页接口

## 通用约定

- 新接口前缀：`/api/v1`；需要独立红娘后台的 `Authorization: Bearer <access_token>`。
- 后台账号必须有效。`/admin/dashboard` 还需要 `dashboard.read` 或 `*` 权限。
- 新接口直接返回 JSON 对象；捕获到的旧路径保留 `{code,data,msg,success}` 包装，仅用于前端迁移。
- 所有统计按当前后台账号的 `SELF/STORE/ORGANIZATION/ALL` 数据范围实现；资源范围由 `resource_assignment` 和组织关系判定，不能由客户端传入。首页运营表已包含默认 `tenant_id=1`，后续接入租户主数据时必须由会话解析租户而不是信任 query/body。
- 兼容层不返回账号密码、密码散列、会话、刷新令牌、对象存储密钥或支付密钥。

## `GET /api/v1/admin/bootstrap`

**基本信息**：返回当前操作者、首页头部未读数和短信概况。需要登录；无请求体；成功状态 `200`，响应 `application/json`。

**请求参数**：无。非法示例：未带 `Authorization`，返回 `401`。

**请求示例**：

```http
GET /api/v1/admin/bootstrap
Authorization: Bearer <access-token>
```

无请求体。

**返回参数**：`operator.id/account/name/permissions/locked` 是已脱敏账号身份；`authorization.status/expires_at/sms_remaining_count` 是授权摘要；`header.has_unread_feedback`、`header.unread_announcement_count`、`header.sms.success_count/failed_count/remaining_count` 是顶部状态。所有数量非负，过期时间为空表示当前未配置。

**返回示例**：

```json
{"operator":{"id":1,"account":"admin","name":"管理员","permissions":["*"],"locked":false},"authorization":{"status":"active","expires_at":null,"sms_remaining_count":0},"header":{"has_unread_feedback":false,"unread_announcement_count":0,"sms":{"success_count":0,"failed_count":0,"remaining_count":0}}}
```

**使用方法与业务规则**：进入后台后首先调用；只读、幂等；短信余额来自专用汇总表而非发送量反推；公告未读按管理员账号隔离。建议前端最长缓存 30 秒。

**错误**：`401` 登录失效，清理令牌后重新登录；`403` 账号停用，禁止进入后台；`500` 服务异常，按响应的 `X-Request-ID` 排查。

## `GET /api/v1/admin/dashboard`

**基本信息**：返回首页统计和连续每日趋势。需要登录和 `dashboard.read`；成功 `200`；无请求体。

**请求参数**：`from`、`to` 位于 query，类型为 ISO 日期，均可选，默认最近 15 天；`from <= to` 且跨度 `1..366` 天。合法示例 `?from=2026-08-01&to=2026-08-15`；非法示例 `?from=2026-08-15&to=2026-08-01` 返回 `422`。

**请求示例**：

```http
GET /api/v1/admin/dashboard?from=2026-08-01&to=2026-08-15
Authorization: Bearer <access-token>
```

无请求体。

**返回参数**：`from_date/to_date` 为实际范围。`metrics` 的字段均为当前数据权限范围内的累计值：

| 字段 | 类型 | 必返 | 空值/枚举 | 业务含义 |
| --- | --- | --- | --- | --- |
| `member_count` / `platform_user_count` | integer | 是 | 空库为 `0` | 正常状态平台会员数；两个字段目前同义，保留前端迁移兼容。 |
| `wechat_fan_count` | integer | 是 | 空库为 `0` | 已绑定非空微信 OpenID 的正常会员数。 |
| `online_days` | integer | 是 | 空库为 `0` | 正常会员历史登录日期的去重天数，不是当前在线人数。 |
| `lead_count` / `customer_lead_count` | integer | 是 | 空库为 `0` | 后台客源线索数；两个字段目前同义，保留兼容。 |
| `vip_count` | integer | 是 | 空库为 `0` | 生效且未到期的会员数。 |
| `online_vip_count` / `offline_vip_count` | integer | 是 | 空库为 `0` | 按关联订单是否为 `offline_vip` 商品划分的生效会员数。 |
| `matchmaker_count` / `service_matchmaker_count` | integer | 是 | 空库为 `0` | 审核通过的服务红娘数；两个字段目前同义，保留兼容。 |
| `promotion_matchmaker_count` | integer | 是 | 空库为 `0` | 审核通过的推广红娘（`promoter`）数。 |
| `successful_match_count` | integer | 是 | 空库为 `0` | 已匹配或已聊天的去重配对数。 |
| `male_member_count` / `female_member_count` | integer | 是 | 性别 `1` 男、`2` 女 | 正常状态会员的性别分布。 |
| `pending_withdrawal_count` | integer | 是 | 空库为 `0` | 用户账户处于 `PENDING_REVIEW` 的提现申请数。 |
| `online_income` / `offline_income` | string(decimal) | 是 | 如 `"0.00"` | 已支付订单金额；`offline_income` 仅统计 `offline_vip`，`online_income` 排除该商品。 |

`pending` 为可实际从现有表计算的待处理数：`withdrawal`（提现审核）、`matchmaker_application`（红娘申请）、`matchmaker_service`（待开始服务）、`match_application`（认识申请）、`report`（举报）。`member_gender.male/female/unspecified` 是与上述成员统计同一数据范围的性别分布。`income_rank[]` 最多五项，每项有 `product_type`、两位小数 `income`、百分比 `proportion`。`trends[]` 每个自然日一项，包含 `date/member_count/lead_count/paid_amount/online_paid_amount/offline_paid_amount/completed_refund_amount/net_amount`；净额恒等于实收减已完成退款。

**返回示例**：

```json
{"from_date":"2026-08-01","to_date":"2026-08-01","metrics":{"member_count":0,"platform_user_count":0,"wechat_fan_count":0,"online_days":0,"lead_count":0,"customer_lead_count":0,"vip_count":0,"online_vip_count":0,"offline_vip_count":0,"matchmaker_count":0,"service_matchmaker_count":0,"promotion_matchmaker_count":0,"successful_match_count":0,"male_member_count":0,"female_member_count":0,"pending_withdrawal_count":0,"online_income":"0.00","offline_income":"0.00"},"pending":{"withdrawal":0,"matchmaker_application":0,"matchmaker_service":0,"match_application":0,"report":0},"member_gender":{"male":0,"female":0,"unspecified":0},"income_rank":[],"trends":[{"date":"2026-08-01","member_count":0,"lead_count":0,"paid_count":0,"completed_refund_count":0,"paid_amount":"0.00","online_paid_amount":"0.00","offline_paid_amount":"0.00","completed_refund_amount":"0.00","net_amount":"0.00"}]}
```

**使用方法与业务规则**：首页加载后调用；只读、幂等；无数据日期仍补零；待支付订单不计收入，退款只按完成退款时间扣减。支付日会保留原始实收，退款日单独扣减，因此跨日退款不会产生错误负收入。建议缓存 30 至 60 秒。

**错误**：`401` 未登录；`403` 缺少 `dashboard.read`；`422` 日期格式或范围错误；`500` 数据库异常。

**变更记录（2026-08-17）**：在原有响应上新增 `metrics` 的平台、微信、会员拆分、红娘拆分、成功匹配和性别字段；新增 `pending`、`member_gender`、`income_rank`；趋势新增线上/线下实收字段。全部为向后兼容的新增字段，旧客户端可忽略，原字段未删除或改名。

## `GET /api/v1/admin/announcements`

**基本信息**：分页读取当前管理员可见的已发布更新公告。需要登录；成功 `200`；无请求体。

**请求参数**：`page` query，默认 `1`、最小 `1`；`page_size` 默认 `20`、范围 `1..100`；`category` 最长 64；`keyword` 最长 100，可按标题或 ID 搜索。非法示例：`page_size=101` 返回 `422`。

**返回参数**：`items` 中每项含公告 ID、版本、类别、标题、样式、排序、链接、创建时间和当前管理员的 `read`；分页字段含 `page/page_size/total/has_more`。`version_id`、`title_color`、`link_to` 可为空。

**返回示例**：

```json
{"items":[],"page":1,"page_size":20,"total":0,"has_more":false}
```

**使用方法与业务规则**：只有 `published_at` 非空的公告可见；排序为置顶、排序值、发布时间、ID；已读关系按账号存储，不影响其他管理员。该批未新增标已读写接口，因此前端不能通过列表请求改变已读状态。

**错误**：`401` 未登录；`422` 分页或搜索参数非法；`500` 查询失败。

## `GET /api/v1/admin/academy/categories` 与 `GET /api/v1/admin/finance/recharge-items`

**基本信息**：前者返回已启用的两级婚创学苑栏目树，后者返回已启用的只读资源套餐。均需要登录、无请求体、成功 `200`。

**请求参数**：无；未带令牌是非法示例，返回 `401`。

**返回参数**：栏目含 `id/parent_id/name/description/image/category_type/sort/enabled/matchmaker_class_enabled/children`；套餐含 `id/name/resource_type/quantity/price`，`price` 是两位小数字符串。

**使用方法与业务规则**：栏目只返回 `Guides` 且启用的数据，按 `sort,id` 稳定排序；套餐只展示价格和数量，绝不创建订单、加余额或扣款。支付必须使用独立、幂等且经回调验签的写接口。

**错误**：`401` 未登录；`500` 查询失败。

## 旧路径兼容层与变更记录

已实现抓取文档列出的 20 个 `GET /common/api`、`GET /commonadmin/api` 和 `GET /loveadmin/api` 路径，并同时注册原始路径与 `/api/v1` 前缀路径，例如 `GET /commonadmin/api/system/getTenantData` 和 `GET /api/v1/commonadmin/api/system/getTenantData`。它们保持旧包装、分页字段和 `sendSucess` 拼写；`netAmount` 是订单统计新增字段，向后兼容。图像配置去除了旧接口中的 `accessKey`，这是必要的安全性变更，前端应使用项目既有的认证上传接口。

旧接口无请求体；其查询参数遵循抓取文档：分页最小 1，`limit <= 100`（趋势接口 `<=366`），`dateStatisticType` 仅 `Day|Month`，`type` 仅 `Guides`。错误处理与上述新接口一致。

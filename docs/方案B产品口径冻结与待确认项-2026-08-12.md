## 2. C-06 决策结果

1. 复用现有社区帖子的视频媒体能力，视频仍是社区帖子的一种媒体形态。
2. 本期不建立独立“短视频频道、短视频推荐流、短视频账号体系、独立评论体系”。
3. 现有社区评论与内容审核能力继续作为新内容的基础能力；旧评论后台是否迁移，须先完成数据盘点。
4. 存量短视频、旧评论和历史媒体不在本期直接迁移。迁移前必须形成数量、格式、存储位置、归属用户、审核状态、隐私授权、失败处理和回滚清单。
5. 四份补充 Markdown 不能据此改变 XMind 和例会确定的社区架构。

因此，C-06 的“范围决策”已完成；任何迁移代码、兼容接口或运营入口仍属于后续工作。

## 3. 已冻结的实现边界

### 3.1 红娘联系方式

当前继续沿用已有的付费/授权同意逻辑。新增的 WECHAT、PHONE 会话请求只记录双方申请、接受、拒绝、撤回和过期状态，不自动返回联系方式明文。

在产品确认前冻结以下行为：

- 不因红娘后台账号拥有读取权限而直接展示用户微信或电话。
- 不因结构化请求状态变为 ACCEPTED 就绕过既有付费、隐私或授权规则。
- 不把红娘申请审核资料中的微信字段直接发布到公开红娘主页。

### 3.2 申请认识拒绝额度

拒绝额度继续保持当前“同一 UTC 自然日”口径。本期不改为北京时间自然日、滚动 24 小时或按会员等级动态计算，直到产品给出明确规则和存量数据处理方案。

### 3.3 会话删除

`DELETE /api/v1/chat/sessions/{session_id}` 冻结为“当前用户单侧隐藏”，不是物理删除。消息数据继续保留；对方的新消息会恢复接收方隐藏的会话。前端文案不得使用“永久删除聊天记录”。

### 3.4 权限和数据范围

红娘后台权限采用显式权限码，`*` 仅表示明确授予的超级权限。无权限记录不等于超级管理员。

`data_scope` 枚举冻结为：

- `SELF`：本人数据
- `STORE`：门店数据
- `ORGANIZATION`：组织数据
- `ALL`：全局数据

字段和账号持久化契约已经实现，但在所有业务 SQL 完成范围过滤前，不得宣称组织数据隔离已完成。

## 5. 外部依赖冻结

以下能力在外部条件就绪前只能保留接口设计或本地逻辑，不得标记生产完成：

- 真实支付渠道、异步支付回调、退款回调和签名验签。
- 微信订阅消息模板、AppID、密钥、用户授权和发送额度。
- 可用的测试 MySQL、Redis 和真实 HTTP 环境。
- 生产迁移窗口、备份、回滚脚本和运维审批。
- 日志平台、指标平台、告警渠道和灰度功能开关。

## 6. 变更控制

后续若修改以上冻结结论，应先更新本文件和对应产品决策记录，再修改 Schema、数据库、服务和前端；不得仅依据补充 Markdown 或单个接口实现反向改变产品架构。

## 一、执行规则

1. 本清单只描述修改范围和验收要求，不代表相关功能已经完成。
2. 新增或修改接口必须同步更新 `docs/api/*`，并满足 `PROJECT_RULES.md` 中关于 URL、权限、请求参数、返回字段、错误码、状态流转、幂等和示例的要求。
3. 所有资金、积分、次数、联系方式、实名、人脸、消息和组织数据都必须在服务端校验，不能依赖前端限制。
4. 所有后台查询必须明确管理员身份、权限码、数据范围和资源归属；不能只做登录校验。
5. 所有跨模块事件必须明确事务边界、幂等键、重试策略、失败补偿和审计记录。
6. 每项完成后必须补充单元测试、越权测试、真实数据库测试或明确记录阻塞原因。

## 二、优先级和状态定义

| 优先级 | 含义 |
| --- | --- |
| P0 | 安全、权限、数据隔离、资金和一期主流程阻塞项，必须优先完成 |
| P1 | 产品主流程和后台运营能力，影响完整验收 |
| P2 | 实时通信、AI 扩展、统计、迁移和体验增强 |

状态使用：`未开始`、`进行中`、`部分完成`、`已完成`、`阻塞待确认`。

## 五、红娘后台管理修改清单

### MA-01 全量 RBAC 权限落地

- 优先级：P0
- 当前状态：部分完成
- 修改内容：
  - 为账号管理、会员、红娘、商品、服务单、门店、资源、约见、财务、提现和报表定义细粒度权限码。
  - 所有后台路由显式调用权限校验，不允许仅依赖 `get_current_matchmaker_admin` 登录检查。

- 验收标准：无权限返回 `403`；权限修改即时生效；管理员不能授予自身超出授权范围的权限。

### MA-02 数据范围 SQL 隔离

- 优先级：P0
- 当前状态：部分完成
- 修改内容：

  - 对 URL 中的门店、组织、会员和红娘 ID 做资源归属校验。
  - 增加跨门店、跨组织、禁用账号和无效绑定测试。
- 验收标准：低范围账号无法通过改变 query、path 或 body ID 读取或修改其他组织数据；所有查询均有范围审计信息。

- 优先级：P0

  - 统一登录、刷新、退出、会话撤销、密码重置和设备管理。
  - 对登录、授权失败、敏感读取、退款、提现、资源调整和资料发布写入审计日志。
  - 日志不得写入密码、Token、证件原图和联系方式明文。
- 验收标准：同一后台工作流可使用统一身份完成；敏感操作可按账号、时间、资源和结果追溯。

### Main interfaces

- `GET /api/v1/admin/matchmaker/service-requests`: scope-filtered service request listing.
- `PATCH /api/v1/admin/matchmaker/service-requests/{service_id}`: permission- and scope-filtered service request update.

- Public matchmaker list/detail: returns only approved, active users with an active service-matchmaker role.

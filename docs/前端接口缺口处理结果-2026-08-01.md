# 前端接口缺口处理结果

日期：2026-08-01

本文以当前后端代码、路由和数据库初始化脚本为准，前端请按“已完成”部分联调；不要继续使用已废弃路径或本地 Mock 伪造成功状态。

## 一、已完成，可直接联调

### 1. 谁收藏我

```http
GET /api/v1/discovery/favorites/received?page=1&page_size=20
Authorization: Bearer <token>
```

返回 `items/page/page_size/total/has_more`。每条记录包含：

```json
{
  "id": 101,
  "user": {"user_id": 23, "nickname": "小明", "avatar": "/storage/uploads/23/avatar.webp", "age": 29, "city_code": "310100"},
  "relation": "received",
  "created_at": "2026-08-01T08:00:00"
}
```

这是“收藏”关系，不是“喜欢”或认识申请。注销、隐藏资料、暂停交友及互相拉黑的用户不会返回。

### 2. 我的爆灯、谁给我爆灯

```http
GET /api/v1/discovery/superlikes/sent?page=1&page_size=20
GET /api/v1/discovery/superlikes/received?page=1&page_size=20
```

返回分页字段和记录字段：`id`、`user`（用户摘要）、`direction`、`status`、`created_at`、`matched`、`order_no`。`order_no` 仅当前用户自己的记录可见。两接口均需要登录，互相拉黑或目标用户不可展示时过滤。

### 3. 我的页面统计

`GET /api/v1/users/me/overview` 已增加：

`visitor_count`、`favorite_count`、`favorite_received_count`、`superlike_sent_count`、`superlike_received_count`。

统计口径由后端统一计算，前端不要保留固定演示数字。`incoming_application_count` 和 `outgoing_application_count` 仍表示待处理的收到/发出申请数量。

### 4. 申请记录用户摘要

`GET /api/v1/discovery/applications/incoming` 和 `/outgoing` 的每条记录新增 `from_user`、`to_user`，字段为：`user_id`、`nickname`、`avatar`、`age`、`city_code`。前端不需要为每条申请再次请求用户详情。

申请状态：`0` 待处理、`1` 已同意、`2` 已拒绝、`3` 已过期；只有接收方可以同意/拒绝，重复处理返回 `409`，同意后创建匹配和聊天会话。

### 5. 资料更新契约

- `height`：`140..220` 厘米。
- `weight`：新增，`40..120` 千克。
- `self_intro`：最多 500 字。
- 地址继续传省、市、区 code，不传拼接后的中文地址。
- 未提交的 PATCH 字段保持原值；明确传 `null` 表示清空。
- `income` 当前仍为数值字段，后端没有把前端收入区间字符串直接写入数据库。前端应暂时按 `income: number` 联调；如果产品坚持区间枚举，需要另行确认映射规则后再改契约。
- `interest_tags`、`personality_tags` 非空时各传 3~5 个固定标签；`null` 表示清空/写入空值语义由 PATCH 调用方明确，不能把空数组当作“未修改”。

## 二、已有接口，前端需要调整使用方式

1. 筛选选项路径是 `GET /api/v1/discovery/filter-options`，不是 `/discovery/filters/options`。
2. `GET /api/v1/relations/liked-by` 已废弃并返回 `410`，不能用于“谁收藏我”。
3. 推荐、广场、搜索、详情、历史、访客、我的收藏、申请、举报、拉黑和会员套餐读取已有真实接口；关闭 Mock 后应直接处理接口的空列表、`401`、`403`、`404`、`409`、`422` 和网络失败状态。
4. `204 No Content` 的拉黑/解除拉黑和媒体操作没有 JSON 响应体，前端请求封装不要强制解析 JSON。
5. 搜索至少提交 `nickname` 或 `tag` 一个非空关键词；筛选 `page_size` 最大为 20。

## 三、暂不作为已完成接口

### 爆灯支付

已新增测试支付链路：

```http
POST /api/v1/spotlights/payments
Idempotency-Key: spotlight-demo-001
{"target_user_id": 23}

POST /api/v1/payments/test/pay
{"order_no":"TEST...","success":true}
```

前一个接口创建订单，后一个接口在 development/testing 环境模拟支付并写入爆灯记录，不调用微信。`GET /api/v1/spotlights/payments/{order_no}` 可查询订单。原 `POST /api/v1/discovery/superlikes/{target_id}` 仍是免费/额度爆灯接口，两者不要混用。

### 置顶

已新增测试支付链路：

- `GET /api/v1/boost/packages`
- `GET /api/v1/users/me/boost/status`
- `POST /api/v1/boost/orders`，请求 `{"package_code":"boost_7d"}`，必须带 `Idempotency-Key`
- `GET /api/v1/boost/orders/{order_no}`
- 订单创建后调用 `POST /api/v1/payments/test/pay` 完成测试支付，成功后置顶立即生效。

测试套餐为 `boost_1d`、`boost_7d`、`boost_30d`，价格和有效期由后端返回，前端不要写死。

### 关于我们、客服

当前为静态内容/Toast，不属于本次后端缺口修复范围。若需要运营后台可编辑，再单独确认 `content/about`、FAQ 和客服会话接口。

## 四、联调验收重点

- 所有请求统一确认线上最终前缀：后端逻辑前缀为 `/api/v1`，不要同时混用 `/api/api/v1` 和 `/api/v1`。
- 空列表必须展示空状态，不能填充静态假数据。
- 重复收藏、取消收藏、重复申请、重复爆灯和重复支付分别按接口的幂等/`409`/额度规则处理。
- 真实支付尚未完成前，不要把爆灯或置顶页面标记为支付成功。

对应后端接口文档：`docs/api/discovery.md`、`docs/api/profile.md`。

## 五、无第三方登录时的测试入口

development/testing 环境可使用已有账号的手机号和密码登录：

```http
POST /api/v1/auth/test-login
Content-Type: application/json

{"phone":"13900000001","password":"password123","device_id":"dev-device-01","platform":"devtools","app_version":"test"}
```

返回标准 `access_token`、`refresh_token`、`user_id` 和 `need_bind_phone`。该接口不会创建账号；不存在返回 `404`，密码错误返回 `401`，冻结/注销返回 `403`，生产环境禁止使用。密码必须以 bcrypt 哈希保存到 `users.password`。

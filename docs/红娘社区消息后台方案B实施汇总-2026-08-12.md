## 3. 公共基础与安全修改

### 3.1 红娘后台显式 RBAC

修改 `app/api/dependencies.py`：

- `CurrentMatchmakerAdmin` 增加不可变权限集合和 `require(permission)`。
- 登录态校验后从 `matchmaker_admin_permission` 读取真实权限。
- 缺少权限返回 403；只有显式 `*` 才是超级权限。
- 修复实名认证依赖中的人脸认证乱码文案为“请先完成人脸认证”。

修改 `app/api/routes/matchmaker_admin.py`：

- `GET /api/v1/admin/matchmaker/auth/me` 返回数据库真实权限，不再返回固定权限数组。

敏感接口已接入的权限码：

- 申请读取：`matchmaker.application.read`
- 申请审核：`matchmaker.application.review`
- 后台账号管理：`matchmaker.account.manage`
- 财务读取/写入：`finance.read`、`finance.write`
- 约见读取/写入/反馈读取：`meeting.read`、`meeting.write`、`meeting.feedback.read`

### 3.2 数据范围账号契约

修改账号 Schema、认证服务和账号管理服务：

- 增加 `data_scope=SELF/STORE/ORGANIZATION/ALL`。
- 增加可空 `organization_id`。
- 创建账号时真实写入两个字段。
- 更新账号时支持只修改范围字段。
- 显式传 `organization_id: null` 可清空组织。
- 显式传 `matchmaker_user_id: null` 可解除红娘绑定。

本次只完成“账号契约和持久化”，尚未把范围统一注入会员、资源、财务、约见、申请等全部 SQL。

### 3.3 约见和财务身份修正

修改 `app/api/routes/meeting.py` 与 `app/api/routes/finance.py`：

- 后台接口统一依赖独立红娘后台 Token，不再混用普通用户身份。
- 读写动作增加权限区分。
- 安排约见时使用账号绑定的 `matchmaker_user_id` 作为红娘用户身份。
- 未绑定红娘用户时返回 409，避免错误地把后台账号 ID 写入普通用户字段。

## 6. 消息模块详细修改

### 6.1 同意认识后的自动欢迎

修改 `app/services/discovery.py`：

- 同意申请时在同一数据库事务内创建或复用聊天会话。
- 写入类型 6 的系统消息：“你们已经互相同意认识，可以开始聊天了。”
- 更新最后消息、时间和接收方未读状态。
- 同一会话已存在相同欢迎消息时不重复写入。

### 6.2 会话管理

新增：

- `GET /api/v1/chat/sessions/{session_id}/messages/cursor`
- `PUT /api/v1/chat/sessions/{session_id}/pin`
- `DELETE /api/v1/chat/sessions/{session_id}/pin`
- `DELETE /api/v1/chat/sessions/{session_id}`
- `POST /api/v1/chat/sessions/{session_id}/restore`

行为：

- 置顶按用户独立保存。
- 删除是单侧隐藏，不物理删除消息。
- 对方发送新消息时自动恢复接收方隐藏会话。
- 新游标分页用于稳定加载更早消息，旧页码接口暂时保留。

### 6.3 结构化会话请求

新增：

- `POST /api/v1/chat/sessions/{session_id}/requests`
- `GET /api/v1/chat/sessions/{session_id}/requests`
- `PATCH /api/v1/chat/session-requests/{request_id}`

请求类型：`ANSWER_EXCHANGE`、`LOVE_MODE`、`WECHAT`、`PHONE`。状态：`PENDING`、`ACCEPTED`、`REJECTED`、`WITHDRAWN`、`EXPIRED`。

同一发起人在同一会话中的同类型有效待处理请求不能重复创建；接受/拒绝仅接收人可操作，撤回仅发起人可操作。当前实现只管理申请状态，不自动执行答案交换、恋爱模式切换或联系方式明文展示。

### 6.4 通知分类

新增 `GET /api/v1/notifications/unread-summary`；扩展 `GET /api/v1/notifications` 支持 `notification_type` 筛选。未读汇总按数据库中的通知类型动态分组，未知类型由前端兜底。

公告、微信订阅、模板发送、重试和死信仍未实现。

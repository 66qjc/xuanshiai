# 红娘后台接口文档

版本：v1；基础地址：`/api/v1`；Content-Type：`application/json`。

## 1. 认证约定

红娘后台使用独立账号表 `matchmaker_admin_account` 和独立会话表，不复用 C 端用户登录，也不复用普通管理员登录。项目不提供公开注册接口，账号由后端预置或后续发放给红娘用户。除登录外，所有接口必须携带 `Authorization: Bearer <access_token>`。

账号密码仅用于 `admin/matchmaker/auth/login`，密码服务端只保存 bcrypt 哈希。连续 5 次密码错误会锁定 15 分钟；账号停用后已有 token 立即失效。access token 默认 60 分钟，refresh token 默认 30 天，refresh 时旧会话轮换失效。

统一错误格式：

```json
{"detail":"账号或密码错误"}
```

常见状态码：`400` 参数格式错误，`401` 未登录/令牌失效/登录失败，`403` 账号停用或无权，`404` 资源不存在，`409` 状态冲突，`422` 参数校验失败。

## 2. 认证接口

### 2.1 红娘后台账号密码登录

**基本信息**：`POST /api/v1/admin/matchmaker/auth/login`；无需登录；成功 `200`。

**请求参数**：

| 参数 | 位置 | 类型 | 必填 | 校验与含义 |
| --- | --- | --- | --- | --- |
| `username` | body | string | 是 | 3-64 位，仅允许字母、数字、`_`、`.`、`-`；后台账号名 |
| `password` | body | string | 是 | 8-128 位；登录密码，不能在日志或响应中返回 |

**请求示例**：

```http
POST /api/v1/admin/matchmaker/auth/login
Content-Type: application/json
```
```json
{"username":"mm_zhangsan","password":"CorrectHorseBattery1"}
```

**成功返回**：

```json
{
  "access_token":"<access-token>","refresh_token":"<refresh-token>","token_type":"bearer","expires_in":3600,
  "account":{"id":12,"username":"mm_zhangsan","display_name":"张三","matchmaker_user_id":1001,"status":1,"last_login_at":"2026-08-06T10:00:00"}
}
```

| 返回字段 | 类型 | 必返 | 含义 |
| --- | --- | --- | --- |
| `access_token` | string | 是 | 调用后台接口的短期令牌 |
| `refresh_token` | string | 是 | 刷新 access token 的长期令牌，仅客户端安全存储 |
| `token_type` | string | 是 | 固定为 `bearer` |
| `expires_in` | integer | 是 | access token 有效秒数 |
| `account` | object | 是 | 当前独立后台账号，字段见 2.2 |
| `account.id` | integer | 是 | 后台账号 ID |
| `account.username` | string | 是 | 后台登录名 |
| `account.display_name` | string | 是 | 展示名称 |
| `account.matchmaker_user_id` | integer/null | 是 | 绑定的用户系统红娘 ID；未绑定时为 null |
| `account.status` | integer | 是 | `1` 正常，`2` 停用 |
| `account.last_login_at` | datetime/null | 是 | 最近成功登录时间 |

错误：账号不存在、密码错误、账号停用或锁定均返回 `401` 的统一提示，避免泄露账号是否存在。

### 2.2 查询当前后台账号

**基本信息**：`GET /api/v1/admin/matchmaker/auth/me`；需要登录；成功 `200`。

**请求参数**：无 body。Header：`Authorization: Bearer <access_token>`。

**返回示例**：

```json
{"account":{"id":12,"username":"mm_zhangsan","display_name":"张三","matchmaker_user_id":1001,"status":1,"last_login_at":"2026-08-06T10:00:00"},"permissions":["matchmaker:read","matchmaker:service:write"]}
```

`permissions` 为当前版本固定能力声明；权限不足或 token 非红娘后台 token 返回 `401`，不会接受用户端 token 或普通管理员 token。

### 2.3 刷新令牌

**基本信息**：`POST /api/v1/admin/matchmaker/auth/refresh`；无需 access token，但必须提供有效 refresh token；成功 `200`。

**请求参数**：`refresh_token`，body string，必填，20-512 位；旧 refresh token 使用后立即失效。

**请求示例**：

```json
{"refresh_token":"<refresh-token>"}
```

**返回**：格式与 2.1 完全相同。refresh token 过期、已注销或已轮换返回 `401`。

### 2.4 退出登录

**基本信息**：`POST /api/v1/admin/matchmaker/auth/logout`；需要登录；成功 `204`，无返回体。

Header：`Authorization: Bearer <access_token>`。重复退出返回 `204`；该会话的 access/refresh token 均失效，不影响其他设备会话。

## 3. 红娘与服务接口

以下接口全部使用独立红娘后台 token，并统一校验账号状态和会话有效期。

### 3.1 红娘列表

`GET /api/v1/admin/matchmaker/matchmakers`，需要登录，成功 `200`。

参数：`page` query integer，默认 1，范围 1-1000；`page_size` query integer，默认 20，范围 1-50。列表只返回有效服务红娘，空数据返回 `items: []`。

请求示例：

```http
GET /api/v1/admin/matchmaker/matchmakers?page=1&page_size=20
Authorization: Bearer <access-token>
```

返回示例：

```json
{"items":[{"user_id":1001,"nickname":"张三","avatar":"/storage/uploads/a.jpg","application_type":"service_matchmaker","intro":"专注本地婚恋服务","certification_tags":["平台认证"],"success_count":18,"rating_score":4.8,"rating_count":12,"is_available":true}],"page":1,"page_size":20,"total":1,"has_more":false}
```

返回字段：`items` 红娘数组；`user_id` 红娘用户 ID；`nickname` 昵称；`avatar` 头像；`application_type` 固定 `service_matchmaker`；`intro` 简介；`certification_tags` 认证标签；`success_count` 完成服务数；`rating_score` 平均评分；`rating_count` 评分数；`is_available` 当前是否可接单；`page/page_size/total/has_more` 分页信息。

### 3.2 红娘详情

`GET /api/v1/admin/matchmaker/matchmakers/{matchmaker_id}`，需要登录，成功 `200`。`matchmaker_id` path integer，必须大于等于 1。返回结构与 3.1 的 `items` 单项相同；红娘不存在或已不可用返回 `404`。

### 3.3 服务商品列表与详情

列表：`GET /api/v1/admin/matchmaker/service-products`；详情：`GET /api/v1/admin/matchmaker/service-products/{product_id}`。均需登录，成功 `200`；`product_id` 必须为正整数。列表空数据返回 `[]`，详情不存在/已下架返回 `404`。

商品返回字段：`id` 商品 ID；`code` 唯一编码；`name` 名称；`service_type` `1` 付费牵线、`3` 私人定制；`price` 金额；`description` 描述；`active` 是否上架；`created_at/updated_at` 时间。

### 3.4 新增服务商品

**基本信息**：`POST /api/v1/admin/matchmaker/service-products`；需要登录；成功 `201`。

参数：`code` string 2-32 位小写字母开头且仅含小写字母/数字/下划线；`name` string 1-128；`service_type` integer 枚举 `1/3`；`price` number 大于 0 且不超过 1000000，最多 2 位小数；`description` string 1-2000；`active` boolean 可选默认 true。请求示例：

```json
{"code":"one_to_one_match","name":"一对一牵线","service_type":1,"price":199.00,"description":"红娘一对一牵线服务","active":true}
```

返回新增商品对象，格式见 3.3。编码重复返回 `409`。

### 3.5 修改或下架服务商品

**基本信息**：`PATCH /api/v1/admin/matchmaker/service-products/{product_id}`；需要登录；成功 `200`。

请求 body 可部分更新：`name`、`service_type`、`price`、`description`、`active`，校验规则与 3.4 相同；至少提供一个字段。示例：`{"active":false,"description":"暂时停止售卖"}`。返回更新后的商品对象；不存在返回 `404`。下架为软删除，历史订单不被删除。

### 3.6 服务申请列表

**基本信息**：`GET /api/v1/admin/matchmaker/service-requests`；需要登录；成功 `200`。

参数：`status` query 可选 `0` 待处理、`1` 服务中、`2` 已完成、`3` 已取消；`page` 1-1000 默认 1；`page_size` 1-50 默认 20。返回分页对象：`items`、`page`、`page_size`、`total`、`has_more`。

`items` 字段：`id` 服务申请 ID；`user_id` 购买用户 ID；`matchmaker_id` 当前红娘 ID/null；`service_type` 服务类型；`status` 状态；`order_id` 订单 ID；`product_id` 商品 ID；`requirement` 用户需求；`feedback` 处理说明/null；`created_at`、`updated_at`、`start_at`、`end_at` 时间/null。

### 3.7 分配或处理服务申请

**基本信息**：`PATCH /api/v1/admin/matchmaker/service-requests/{service_id}`；需要登录；成功 `200`。

body 可包含：`matchmaker_id` integer/null，必须为有效服务红娘；`status` integer/null，枚举 `0/1/2/3`；`feedback` string/null，最多 2000 字。至少提供一个字段；设置状态为 `2` 或 `3` 时必须提供非空 `feedback`。

示例：

```json
{"matchmaker_id":1001,"status":1,"feedback":"已分配给张三并开始服务"}
```

允许状态迁移：`0 -> 1/3`，`1 -> 2/3`；其他迁移返回 `409`。返回更新后的服务申请对象；申请不存在返回 `404`，目标红娘无有效红娘角色返回 `422`。更新会记录更新时间并向相关用户发送通知。

## 4. 兼容与边界

### 4.1 红娘统计

`GET /api/v1/admin/matchmaker/statistics`，需要登录，成功 `200`，无请求体。返回 `total` 红娘申请总数、`available` 当前可接单数、`pending_services` 待处理服务单数、`active_services` 服务中数量、`completed_services` 已完成数量、`cancelled_services` 已取消数量。无数据时各数字为 `0`。账号无效返回 `401`；数据库不可用返回 `500`。

### 4.2 停用或恢复红娘接单

`PATCH /api/v1/admin/matchmaker/matchmakers/{matchmaker_id}/status`，需要登录，成功 `200`。path `matchmaker_id` 为正整数；body `status` 必填，`1` 恢复接单、`2` 停止接单；`reason` 可选，最多 255 字，停用时建议填写。示例：`{"status":2,"reason":"服务质量复核中"}`。返回 `{"matchmaker_id":1001,"status":2,"reason":"服务质量复核中"}`。接口同步更新红娘角色状态，停用不会删除历史服务单；无效红娘返回 `404`，并发更新以后一次提交结果为准。

### 4.3 门店接口

`GET /api/v1/admin/matchmaker/branches` 查询门店；`POST /api/v1/admin/matchmaker/branches` 创建门店；`GET /api/v1/admin/matchmaker/branches/{branch_id}` 查询详情；`POST /api/v1/admin/matchmaker/branches/{branch_id}/members` 添加门店成员。全部需要登录。

创建 body：`code` 2-64 位字母/数字/下划线/短横线且唯一；`name` 1-128 字；`display_name` 可选最多 128 字；`region_code` 可选最多 64 字；`auto_redirect` 可选 boolean 默认 false。成员 body：`user_id` 正整数，`role_code` 为 `store_manager` 或 `store_matchmaker`。创建成功 `201`，详情/列表成功 `200`，重复编码、重复成员返回 `409`，用户无对应身份返回 `403`。门店返回字段为 `id/code/name/display_name/region_code/status/auto_redirect/created_at`；成员返回 `id/organization_id/user_id/role_code/status/started_at/ended_at`。

### 4.4 资源分配

`POST /api/v1/admin/matchmaker/assignments` 分配会员资源；`GET /api/v1/admin/matchmaker/assignments` 查询分配记录。需要登录。创建 body：`user_id` 必填正整数；`organization_id` 和 `matchmaker_id` 至少填写一个且为正整数；`source` 枚举 `manual/promotion/default/self_created`，默认 `manual`。同一用户的新分配会结束旧的有效分配，返回 `201`；目标门店不存在、目标红娘无效或缺少目标返回 `404/422`。

查询参数：`page` 默认 1、范围 1-1000；`page_size` 默认 20、范围 1-100；`user_id`、`matchmaker_id` 可选正整数。返回 `items/page/page_size/total/has_more`，`items` 字段为 `id/user_id/organization_id/matchmaker_id/source/status/effective_at/ended_at`；无记录返回 `items: []`。并发分配在事务内先结束旧记录再创建新记录。

### 4.5 安排约见

`POST /api/v1/admin/matchmaker/meetings/requests/{request_id}/schedule`，需要登录，成功 `201`。path `request_id` 为正整数；body 沿用约见安排契约，必须提供 `scheduled_at`、`location`，可提供参与者和组织信息，具体长度/时间校验由 `MeetingScheduleCreate` 执行。已安排、已取消或不存在的申请返回 `409/404`；重复提交不会生成可并存的无效安排。返回 `id/request_id/organizer_id/organization_id/scheduled_at/location/status/cancel_reason/created_at/updated_at`。

## 5. 会员 CRM 接口

以下接口均使用独立红娘后台账号，必须携带 `Authorization: Bearer <access_token>`。

### 5.1 会员列表

`GET /api/v1/admin/matchmaker/members`，成功 `200`。query：`page` 1-1000 默认 1；`page_size` 1-100 默认 20；`gender` 可选 `1/2`；`status` 可选 `1/2/3`；`vip` 可选 boolean；`search` 可选最多 64 字，匹配昵称或手机号。返回 `items/page/page_size/total/has_more`。item 字段：`id`、`nickname`、`phone`、`gender`、`status`、`is_vip`、`vip_end_at`、`matchmaker_id`、`created_at`。无数据返回 `items: []`。非法分页、枚举或超长搜索词返回 `422`。

请求示例：`GET /api/v1/admin/matchmaker/members?page=1&page_size=20&vip=true&search=138`。成功响应示例：`{"items":[{"id":1001,"nickname":"张三","phone":"138****8000","gender":1,"status":1,"is_vip":true,"vip_end_at":"2026-12-01T00:00:00","matchmaker_id":12,"created_at":"2026-08-01T10:00:00"}],"page":1,"page_size":20,"total":1,"has_more":false}`。手机号仅用于后台查询展示，客户端应继续脱敏。

### 5.2 会员统计

`GET /api/v1/admin/matchmaker/members/statistics`，成功 `200`，无请求体。返回 `total` 总会员数、`male` 男性数、`female` 女性数、`vip` 当前有效 VIP 数、`active` 状态正常数；无数据各字段为 `0`。

### 5.3 会员详情

`GET /api/v1/admin/matchmaker/members/{member_id}`，成功 `200`。`member_id` 必须为正整数；返回列表字段及 `avatar`、`birthday`、`is_married`、`residence_city_code`。不存在返回 `404`，未登录返回 `401`。详情仅供已登录红娘后台使用，前端不得缓存手机号等敏感字段。

### 5.4 修改会员状态

`PATCH /api/v1/admin/matchmaker/members/{member_id}/status`，成功 `200`。body：`status` 必填枚举 `1` 正常、`2` 冻结、`3` 注销；`reason` 必填 1-255 字。示例：`{"status":2,"reason":"用户投诉待复核"}`。返回 `id/status/reason`。不存在返回 `404`，参数不合法返回 `422`；每次修改写入 `business_audit_log`，重复提交相同状态不会产生额外业务记录。冻结/注销后的会员仍保留历史服务、订单和会员记录。

## 6. 客源线索接口

所有接口使用 `Authorization: Bearer <access_token>`，未登录返回 `401`。线索状态为 `NEW`、`CONTACTED`、`INTENDED`、`CONVERTED`、`LOST`、`CLOSED`。

### 6.1 列表、统计、详情

`GET /api/v1/admin/customer-leads` 支持 `page` 1-1000、`page_size` 1-100、`status` 状态枚举、`source` 最多 64 字、`matchmaker_id` 正整数和 `search` 最多 64 字。返回 `items/page/page_size/total/has_more`，线索字段为 `id/name/phone/wechat/source/intention_level/status/matchmaker_id/organization_id/next_follow_at/converted_user_id/remark/created_by/created_at/updated_at`。

`GET /api/v1/admin/customer-leads/statistics` 无请求体，返回 `total/new_count/contacted_count/intended_count/converted_count/lost_count`；无数据返回全 0。`GET /api/v1/admin/customer-leads/{lead_id}` 返回单条线索，ID 必须为正整数，不存在返回 `404`。

### 6.2 新增和修改

`POST /api/v1/admin/customer-leads` body：`name` 1-128 字；`phone` 最多 32 字；`wechat` 最多 128 字；`source` 1-64 字；`intention_level` 枚举 `1/2/3`；`remark` 最多 2000 字。手机号和微信号至少提供一个。成功 `201`，示例：`{"name":"李女士","phone":"13900001111","source":"offline_event","intention_level":2,"remark":"希望近期了解牵线服务"}`。

`PATCH /api/v1/admin/customer-leads/{lead_id}` 支持部分更新 `name/phone/wechat/intention_level/status/remark/next_follow_at`，至少提供一个字段；状态值必须使用上述枚举。成功返回更新后的线索，非法状态或空 body 返回 `422`，不存在返回 `404`。更新不删除跟进历史。

### 6.3 跟进和分配

`GET/POST /api/v1/admin/customer-leads/{lead_id}/follow-ups` 查询或新增跟进记录。新增 body：`method` 枚举 `PHONE/WECHAT/VISIT/OTHER`；`content` 1-2000 字；`intention_level` 可选 `1/2/3`；`next_follow_at` 可选时间。新增成功 `201`，线索为 `NEW` 时自动变为 `CONTACTED`。查询支持 `page` 1-1000、`page_size` 1-100，返回记录数组，无数据返回 `[]`。

`PATCH /api/v1/admin/customer-leads/{lead_id}/assignment` 分配线索，body 的 `matchmaker_id` 和 `organization_id` 至少一个；红娘必须是有效服务红娘，门店必须存在且启用。返回更新后的线索；目标无效返回 `422`。所有新增、修改、分配操作写入后台审计日志。

## 7. 后台首页统计

`GET /api/v1/admin/dashboard/stats` 需要独立红娘后台 Token，无请求体，成功 `200`。返回字段：`member_count` 会员总数；`vip_count` 当前有效 VIP 数；`matchmaker_count` 当前可接单红娘数；`pending_service_count` 待处理服务单数；`active_service_count` 服务中服务单数；`pending_certification_count` 待审核红娘申请数；`today_new_member_count` 今日新增会员数。无数据时全部返回 `0`；未登录返回 `401`，数据库异常返回 `500`。

## 8. VIP 与行为查询

`GET /api/v1/admin/members/vip` 需要登录，支持 `page` 1-1000 默认 1、`page_size` 1-100 默认 20、`expiring_within_days` 1-3650 和 `search` 最多 64 字。只返回当前有效 VIP；返回 `items/page/page_size/total/has_more`，item 字段为 `membership_id/user_id/nickname/phone/package_type/amount/order_no/start_at/end_at/status`。无数据返回 `items: []`。本期不提供绕过支付订单直接开通、续期或取消 VIP 的接口。

`GET /api/v1/admin/members/{member_id}/behavior/login-logs` 需要登录，path ID 必须为正整数，query 分页规则同上。返回登录日志分页对象，item 字段为 `id/user_id/nickname/login_status/ip/device_id/platform/failure_reason/created_at`；`login_status` 为 `1` 成功、`2` 失败。无日志返回 `items: []`，不存在用户或无权限返回 `404/401`。IP、设备和失败原因仅供后台风险排查，不得回传到 C 端。

`PATCH /api/v1/admin/members/{member_id}/vip` 管理 VIP，body：`action` 为 `OPEN/RENEW/CANCEL`；`OPEN/RENEW` 必须提供 `package_type` 和 `order_no`；`CANCEL` 必须提供 `reason`。开通/续期时，服务端会锁定并校验该会员的已支付会员订单（订单类型为会员、状态为已支付、套餐匹配），订单已处理时幂等返回原会员记录；没有有效订单返回 `409`，不会直接创建虚假支付或账本流水。续期从当前有效 VIP 到期时间开始计算。

取消 VIP 会将当前有效会员记录置为已取消并写入审计日志，不自动退款；如需退款必须调用财务退款接口。成功返回 `membership_id/user_id/action/package_type/status/start_at/end_at/order_no/reason`。并发请求通过订单和会员行锁保证同一订单只处理一次。

## 9. 活动管理接口

所有活动后台接口均需独立红娘后台 Token。活动状态：`1` 招募中、`2` 已满、`3` 进行中、`4` 已结束、`5` 已取消；报名状态：`0` 待审核、`1` 成功、`2` 已取消、`3` 已拒绝。

`GET /api/v1/admin/activities` 支持 `page/page_size/status/city/search`，分页范围分别为 1-1000、1-100、状态 1-5、城市最多 64 字、标题搜索最多 128 字；返回 `items/page/page_size/total/has_more`。活动字段为 `id/title/cover/type/city/address/start_time/end_time/signup_deadline/max_people/current_people/price/status/description/created_by/created_at`。

`POST /api/v1/admin/activities` 新增活动，body 必填 `title`、`start_time`、`end_time`，可选封面、类型、城市、地址、报名截止时间、人数上限、价格和描述；结束时间必须晚于开始时间，报名截止时间不能晚于开始时间。成功 `201`，示例：`{"title":"周末脱单局","city":"深圳","start_time":"2026-09-01T14:00:00","end_time":"2026-09-01T18:00:00","max_people":30,"price":99}`。

`GET/PATCH /api/v1/admin/activities/{activity_id}` 查询或部分修改活动；ID 必须为正整数，修改至少提供一个字段，时间校验与新增一致。`PATCH /api/v1/admin/activities/{activity_id}/status` body 为 `status` 和可选 `reason`，用于上下线和活动状态处理。活动不存在返回 `404`，状态或参数错误返回 `422/409`；修改不删除报名记录。

`GET /api/v1/admin/activities/{activity_id}/signups` 查询报名，支持 `page/page_size/status`，返回报名分页对象，报名字段为 `id/activity_id/user_id/nickname/real_name/phone/remark/status/cancel_reason/created_at/updated_at`。

`GET/PATCH /api/v1/admin/activity-signups/{signup_id}` 查询或审核报名。PATCH body：`status` 必填 `1/2/3`，`reason` 可选最多 255 字；已取消或已拒绝的报名不能再次审核，返回 `409`。所有审核写入后台审计日志。

## 10. 财务与分成接口

以下 `/api/v1/admin/finance/*` 接口已统一使用独立红娘后台 Token，并复用现有账本、订单幂等和状态迁移逻辑。

`POST /api/v1/admin/finance/commission-rules` 创建分成规则，body：`beneficiary_type` 枚举 `service_matchmaker/store/promoter/partner`；`name` 1-128 字；`mode` 为 `fixed/rate`；fixed 模式必须提供 `fixed_amount`，rate 模式必须提供 `rate_percent`（0-100）；`priority` 0-100000。成功 `201`。

`GET /api/v1/admin/finance/commission-rules` 查询当前有效规则，成功 `200` 返回规则数组。`POST /api/v1/admin/finance/product-commission-rules/{product_id}` 为红娘服务商品配置分成，商品 ID 必须为正整数，规则参数同上；新版本会停用旧版本，不删除历史规则。

`GET /api/v1/admin/finance/report` 返回分成汇总数组，字段为 `beneficiary_type/beneficiary_id/order_count/total_amount/pending_amount/available_amount`。无数据返回 `[]`。

`POST /api/v1/admin/finance/orders/{order_id}/settle` 仅开发/测试环境允许模拟支付并结算，生产环境返回 `503`，必须等待真实支付回调；重复结算依靠订单和分成幂等键返回相同结果。`POST /api/v1/admin/finance/orders/{order_id}/refund` body 为必填 `reason`（1-255 字），仅支付成功订单可退款，退款会冲正分成并关闭关联红娘服务和约见，成功 `204` 无返回体。

`POST /api/v1/admin/finance/commission-entries/{entry_id}/release` 释放待结算分成，只有 `PENDING` 可变更为 `AVAILABLE`，重复或非法状态返回 `409`。`PATCH /api/v1/admin/finance/withdrawals/{withdrawal_id}` 审核提现，body 的 `status` 枚举 `APPROVED/REJECTED/PROCESSING/SUCCEEDED/FAILED`，失败状态可填 `failure_reason`；状态迁移不合法返回 `409`，退款/冲正通过账本记录，不直接修改余额。

## 11. 会员跟进与行为

`GET/POST /api/v1/admin/members/{member_id}/follow-ups` 查询或新增会员 CRM 跟进记录。path ID 必须为正整数；新增 body：`method` 枚举 `PHONE/WECHAT/VISIT/OTHER`，`content` 1-2000 字，`next_follow_at` 可选时间。查询返回 `items/page/page_size/total/has_more`，记录字段为 `id/user_id/method/content/next_follow_at/created_by/created_at`；新增成功 `201`，不存在会员返回 `404`，操作写入审计日志。

`GET /api/v1/admin/members/{member_id}/behavior` 查询会员行为流水，支持 `page` 1-1000、`page_size` 1-100，返回 `items/page/page_size/total/has_more`。item 字段：`event_type` 枚举 `login/browse/favorite/swipe/apply`；`event_id` 原始记录 ID；`target_user_id` 目标用户 ID/null；`target_nickname` 目标昵称/null；`detail` 行为说明；`occurred_at` 发生时间。数据按时间倒序，空数据返回 `items: []`。

## 12. 个人余额支付会员

会员用户先调用 `POST /api/v1/membership/orders` 创建会员订单，再调用 `POST /api/v1/membership/orders/{order_no}/pay-with-balance` 使用个人可用余额支付。Header 必须携带 `Authorization: Bearer <user-token>` 和 `Idempotency-Key`（8-128 位）。接口仅允许支付当前用户自己的会员订单，订单必须未支付且未过期。

成功返回 `MembershipOrderResponse`：`order_no`、`package_code`、`product_name`、`amount`、`status=1`、`expire_at`、`payment_required=false`；支付方式在服务端记录为余额。余额不足返回 `409`，订单不存在返回 `404`，订单已支付/已关闭/已过期返回 `409`。接口在事务内锁定订单和用户账本，按 `CREDIT - DEBIT` 计算可用余额，写入 `membership_order` 扣款流水和会员权益；同一订单重复请求幂等返回已支付结果，不重复扣款。

示例：

```http
POST /api/v1/membership/orders/VIP20260807123456ABC/pay-with-balance
Authorization: Bearer <user-token>
Idempotency-Key: vip-balance-pay-001
```

余额支付不会伪造微信支付回调；退款应通过财务退款流程冲正订单和账本。个人余额来源仍需通过已实现的分成、退款冲正或其他合法账本入账流程产生。

用户端 `/matchmakers`、`/matchmaker/service-products` 继续保持原有行为，供 C 端使用；本文件新增的管理查询即使业务字段复用，也使用 `/admin/matchmaker/*` 路径并单独鉴权。后台账号与用户账号不是同一主体，`matchmaker_user_id` 仅用于后续绑定业务数据，不作为登录凭据。涉及账号发放、权限扩展、账号停用和审计日志时，应通过受控后台或数据库运维流程完成，暂不提供公开注册接口。
\n## 十一、后台可配置任务奖励

以下接口均要求独立红娘后台 Token：`Authorization: Bearer <matchmaker-admin-access-token>`，不接受用户端 Token。数据表为 `config_reward_rule`，新增、修改、删除会写入 `business_audit_log`。

### 11.1 查询任务规则

`GET /api/v1/admin/reward-rules?active_only=false`，无需请求体，成功 `200`。`active_only` 为可选 query boolean，默认 `false`，设为 `true` 仅返回启用规则。

返回字段：`id` 规则 ID；`task_code` 唯一任务编码；`task_name` 名称；`task_type` 1新手/2日常/3成长；`reward_type` 1积分/2纸飞机次数/3会员天数/4曝光卡/5牵线次数；`reward_value` 奖励数量；`daily_limit` 每日上限，0表示不限；`is_active` 0停用/1启用；`sort` 排序；`created_at`、`updated_at` 时间。

```json
[{"id":1,"task_code":"daily_login","task_name":"每日登录","task_type":2,"reward_type":1,"reward_value":5,"daily_limit":1,"is_active":1,"sort":1,"created_at":"2026-08-07T12:00:00","updated_at":"2026-08-07T12:00:00"}]
```

### 11.2 新增任务规则

`POST /api/v1/admin/reward-rules`，`Content-Type: application/json`，成功 `201`，返回完整规则对象。

| 参数 | 位置/类型 | 必填 | 校验与含义 |
|---|---|---|---|
| `task_code` | body/string | 是 | 2-64位，小写字母开头，仅允许小写字母、数字、下划线，唯一 |
| `task_name` | body/string | 是 | 1-64位，任务名称 |
| `task_type` | body/integer | 否 | 1/2/3，默认1 |
| `reward_type` | body/integer | 否 | 1-5，默认1，分别表示积分、纸飞机次数、会员天数、曝光卡、牵线次数 |
| `reward_value` | body/integer | 否 | 0-2147483647，默认0 |
| `daily_limit` | body/integer | 否 | 0-2147483647，0表示不限，默认0 |
| `is_active` | body/integer | 否 | 0或1，默认1 |
| `sort` | body/integer | 否 | 0-2147483647，默认0 |

请求示例：
```json
{"task_code":"daily_share","task_name":"每日分享","task_type":2,"reward_type":1,"reward_value":10,"daily_limit":1,"is_active":1,"sort":4}
```

### 11.3 修改和删除

`GET /api/v1/admin/reward-rules/{task_code}` 查询单条规则，无请求体，成功 `200`。

`PATCH /api/v1/admin/reward-rules/{task_code}` 修改规则，Body 只提交需要修改的字段，例如 `{"reward_value":20,"is_active":1}`，成功 `200` 返回修改后的完整规则。不存在返回 `404`，校验失败返回 `422`。

`DELETE /api/v1/admin/reward-rules/{task_code}` 删除规则，无请求体，成功 `200` 返回 `{"task_code":"daily_share","deleted":true}`。删除配置不会回滚已经发放的奖励。

### 11.4 每日登录自动奖励

初始化默认规则 `daily_login`：奖励类型为积分，奖励值5，每日上限1，默认启用。用户任一成功登录入口创建会话时自动发放；同一用户同一自然日只发放一次，重复登录不会重复记账。该规则不出现在用户手动领取任务列表中。后台可通过 PATCH 修改奖励值或停用规则，历史发放不受影响。

错误响应统一为 `{"detail":"错误说明"}`：未登录或 Token 类型错误 `401`，任务编码冲突 `409`，参数校验失败 `422`，规则不存在 `404`。

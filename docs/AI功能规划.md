# AI 功能分阶段规划

更新时间：2026-08-19

本文档记录 AI 助手、AI 搜索、AI 匹配度及相关文字/图片能力的产品和技术路线。当前项目已有发现、资料、聊天、海报、积分/额度和内容审核能力；AI 功能在这些能力上扩展，不另建用户、资料和推荐系统。

## 一、范围和状态

| 阶段 | 目标 | 当前状态 |
|---|---|---|
| 阶段一 | 文字 AI 基础闭环：AI 助手、聊天用心度、资料文字润色、自然语言搜索、四类匹配解释 | 已实现基础代码，需完成真实环境联调和验收 |
| 阶段二 | 图片美化、海报 AI 文案和视觉参数增强 | 规划中，图片供应商待确认 |
| 阶段三 | 用户向量、语义检索、混合排序和更精细的 AI 匹配 | 规划中，需真实数据和算法评估 |

所有阶段均要求：登录校验、会员权限、额度控制、输入脱敏、风险拦截、输出结构校验、调用记录、失败降级和用户投诉/删除机制。

## 二、总体架构

### 2.1 Provider 适配层

统一使用 OpenAI Chat Completions 兼容协议，业务代码不直接依赖供应商字段。测试环境可配置中转站 GPT，生产环境计划使用 DeepSeek。

```env
AI_ENABLED=true
AI_BASE_URL=https://your-relay.example.com/v1
AI_API_KEY=YOUR_TEST_RELAY_KEY
AI_MODEL=gpt-4o-mini
```

```env
AI_ENABLED=true
AI_BASE_URL=https://api.deepseek.com/v1
AI_API_KEY=YOUR_DEEPSEEK_API_KEY
AI_MODEL=deepseek-chat
```

API Key、Secret、回调地址和供应商合同信息不得写入代码或提交到 Git。生产环境不使用 Mock 响应。

### 2.2 统一调用链

```text
用户请求
 -> 登录、会员和资源权限校验
 -> Redis/积分额度校验
 -> 输入脱敏和风险检查
 -> AI Provider
 -> JSON/Schema 输出校验
 -> AI 输出安全审核
 -> 保存必要的结果和调用审计
 -> 返回前端
```

AI 不能直接决定用户是否违规、是否适合交往、是否可见、是否封禁或是否建立匹配关系。最终业务判断仍由后端规则和人工流程完成。

## 三、阶段一：文字 AI 基础闭环

### 3.1 AI 助手

#### 功能

- 创建和查询 AI 助手会话。
- 用户发送问题，AI 返回婚恋沟通建议。
- 默认允许 AI 查看当前用户作为发送方或接收方的文本聊天记录，读取最近最多 80 条；撤回消息不进入上下文。
- 重点场景：评估用户聊天是否用心、分析对方是否回应具体问题、指出敷衍或沟通断点、给出下一句建议。
- AI 必须明确自身为 AI，不得伪装真人红娘。

#### 接口

```text
POST /api/v1/ai/assistant/sessions
GET  /api/v1/ai/assistant/sessions
POST /api/v1/ai/assistant/sessions/{session_id}/messages
```

#### 数据

新增 `ai_assistant_session`、`ai_assistant_message`。会话和消息只能由所属用户访问；消息记录需要支持删除策略、模型版本、提示词版本、风险等级和调用流水关联。

#### 安全边界

对自伤/他伤、未成年人、诈骗、骚扰、色情、医疗、法律、金融和联系方式索取等场景拦截或转人工。AI 不作诊断、法律结论或成功概率承诺。

### 3.2 聊天用心度

#### 输出维度

- 回复是否具体回应对方问题。
- 是否有主动提问和有效信息。
- 是否持续接住对方的情绪和话题。
- 是否存在大量敷衍语气、复制粘贴或回避。
- 是否有尊重、边界和推进沟通的表现。

#### 输出结构

```json
{
  "score": 82,
  "level": "较用心",
  "summary": "能够回应对方的具体问题，也有主动分享。",
  "strengths": ["回复具体", "有主动提问"],
  "suggestions": ["适当回应对方情绪"],
  "evidence": [{"message_id": 123, "reason": "回答了对方的问题"}]
}
```

用心度只作反馈，不用于封禁、降低曝光或替代人工判断。需要明确评价对象是“当前用户自己的聊天表现”，不能宣称“对方一定喜欢你”。

### 3.3 AI 文字润色

#### 功能

- 润色自我介绍、择偶要求和首页短文案。
- 支持自然、温柔、幽默、成熟、简洁风格。
- 保留用户原始意图，不凭空添加职业、收入、学历、房产、身份或经历。
- 返回原文、润色稿和修改点；用户确认后才调用现有资料接口保存。

#### 接口

```text
POST /api/v1/ai/profile/polish
```

当前只处理文字，不包含图片美化。具体契约见 `docs/api/AI能力.md`。

### 3.4 AI 自然语言搜索

#### 功能

将“找一个 28 到 35 岁、杭州、喜欢旅行和摄影、性格开朗的人”解析为现有发现筛选条件，再复用发现服务的隐私、拉黑、关系和排序规则。

#### 接口

```text
POST /api/v1/ai/search
```

AI 只解析查询，不直接生成用户列表。无法确定的条件放入 `unresolved`；解析失败时可以降级为普通搜索或要求用户补充条件。结果保持 `DiscoveryPage` 兼容结构。

### 3.5 四类 AI 匹配度

首页预留四个标签：

| 标签 | 说明 |
|---|---|
| 谁会喜欢我 | 根据对方择偶偏好、资料和已有互动，估算对方与当前用户的匹配程度 |
| 我会喜欢谁 | 根据当前用户的择偶要求、资料、兴趣和性格，计算候选人匹配程度 |
| 物质匹配 | 年龄、城市、学历、身高、收入、婚姻等字段的内部匹配；只遵守隐私设置后返回概括结果 |
| 灵魂匹配 | MBTI、兴趣、性格标签、生活方式和活跃度，不使用收入、房产等物质字段 |

#### 接口

```text
GET /api/v1/ai/matches/who_likes_me
GET /api/v1/ai/matches/i_like
GET /api/v1/ai/matches/material
GET /api/v1/ai/matches/soul
```

#### 评分原则

当前阶段复用 `_candidate_score` 的规则分和分项数据。AI 只生成 `match_reason`、风险提示和 `suggestions`，不能改写分数、绕过隐私、直接建立关系。

物质字段可以参与内部计算，但具体展示必须遵守用户隐私设置；响应不返回对方精确收入、房产或其他未授权敏感值。灵魂匹配目前主要依据 MBTI、兴趣和性格，不把 MBTI 单项结果包装成确定性的关系结论。

## 四、阶段二：图片和海报 AI

### 4.1 一键图片美化

#### 第一版允许的能力

- 亮度、对比度和色彩优化。
- 清晰度增强。
- 轻度磨皮和光线修复。
- 轻度背景虚化和构图裁剪。

#### 第一版禁止的能力

- 改脸型、年龄、身材或身份特征。
- 生成不存在的人物。
- 修改证件、合同、品牌和重要文字。
- 通过 AI 处理绕过原有媒体审核。

#### 流程

```text
原图上传 -> 原图审核 -> AI 处理 -> 结果图审核 -> 预览 -> 用户确认 -> 生成新媒体记录
```

不覆盖原图，结果作为新的 `user_media` 记录。预计接口：

```text
POST /api/v1/ai/images/{media_id}/enhance
GET  /api/v1/ai/image-jobs/{job_id}
POST /api/v1/ai/image-jobs/{job_id}/apply
DELETE /api/v1/ai/image-jobs/{job_id}
```

美图秀秀仅作为候选供应商，尚未确定。接入前必须确认服务端 API、异步回调、数据地域、保存期限、删除能力、婚恋场景授权、价格、限流和签名方式。

### 4.2 海报 AI 润色

复用现有海报生成接口，AI 只负责文案和布局参数建议，服务端负责最终排版，避免文字溢出和恶意图片生成。预计接口：

```text
POST /api/v1/users/{user_id}/poster/ai-preview
POST /api/v1/users/{user_id}/poster/ai-generate
```

支持标题、自我介绍短文案、匹配理由、风格和头像裁剪建议。用户确认后生成最终海报。

## 五、阶段三：向量和精细化匹配

### 5.1 用户向量

为公开且获得授权的资料生成向量：自我介绍、兴趣、性格、MBTI、择偶要求、城市和基础条件。手机号、身份证、聊天原文、精确收入等敏感数据不进入向量。

预计数据：`user_profile_embedding`，记录用户、模型、版本、源数据哈希、更新时间和向量内容。用户资料修改、删除或撤回授权时必须同步更新或删除向量。

### 5.2 混合搜索和排序

```text
硬性条件过滤
 -> 隐私、拉黑、关系和账号状态过滤
 -> 规则匹配分
 -> 语义相似度
 -> 活跃度和安全分
 -> 可解释的结果重排
```

初始建议权重：硬性条件 40%、规则匹配 25%、语义相似度 20%、活跃度 10%、安全分 5%。上线前必须用真实数据、人工标注和灰度实验校准，不能直接让模型决定排序。

### 5.3 精细化匹配

- 保存匹配分维度和模型版本。
- 支持匹配结果缓存和重新计算。
- 支持推荐实验、权重版本、回滚和效果统计。
- 增加用户对匹配结果“不准确”的反馈入口。
- 将匹配原因、数据完整度和不确定性展示给用户。

## 六、会员、额度和成本

阶段一和后续 AI 功能默认仅会员可用。当前阶段一默认每日额度：

| 功能 | 默认额度 |
|---|---:|
| AI 助手消息 | 20 条 |
| 资料文字润色 | 5 次 |
| AI 搜索 | 10 次 |
| AI 匹配查询 | 10 次 |

额度使用 Redis 原子扣减；AI 调用失败应退还额度。后续可增加积分购买额外次数，产品需要确认会员档位、额度差异、图片费用和超额策略。

## 七、隐私、安全与合规门禁

- 用户必须知道 AI 是 AI，不能伪装真人。
- 聊天记录默认只用于本人 AI 助手，不能用于其他用户画像或公开展示。
- 发送给第三方模型前必须做敏感字段脱敏，并确认供应商是否训练使用数据、存储地域和删除承诺。
- 支持 AI 会话删除、资料生成记录删除和必要的模型调用审计。
- AI 输出经过风险检查；高风险场景拦截或人工转接。
- 物质匹配只使用获得授权且符合隐私设置的字段。
- 生产上线前确认 AI 服务定性、算法推荐备案适用性、隐私政策、用户授权、投诉和人工复核流程。

## 八、阶段验收标准

### 阶段一

- [ ] 会员用户可以创建 AI 会话并完成一轮对话。
- [ ] AI 能基于本人聊天记录返回用心度分析或沟通建议。
- [ ] 非会员、未登录、额度耗尽、AI 超时和 Redis 故障均返回明确错误。
- [ ] 资料润色不会自动写回，且不会编造用户事实。
- [ ] 自然语言搜索能解析结构化筛选，并继续遵守现有隐私和关系过滤。
- [ ] 四类匹配均返回分项分、原因和建议，物质字段不泄露未授权值。
- [ ] Mock、中转站 GPT 和 DeepSeek 三种配置路径完成联调。

### 阶段二

- [ ] 原图、结果图均完成审核。
- [ ] 结果图不覆盖原图，用户确认后才写入媒体记录。
- [ ] 第三方图片服务具备超时、重试、回调验签和删除机制。
- [ ] 海报文字不溢出，AI 失败可回退到原有海报生成。

### 阶段三

- [ ] 向量只包含授权公开资料，用户删除资料后向量同步删除。
- [ ] 硬性条件、隐私和安全规则优先于语义排序。
- [ ] 模型、权重、提示词和数据版本可追溯、可回滚。
- [ ] 通过人工标注、灰度实验和推荐安全评估后再扩大流量。

## 九、待确认决策

1. “AI 用心度”是否只评价当前用户自己的聊天表现，还是允许评价双方互动质量。
2. 阶段一正式模型是否使用 DeepSeek，测试中转站的供应商、地域和数据训练条款。
3. 阶段二图片供应商是否采用美图秀秀，以及图片是否允许发送到第三方。
4. 会员不同套餐的 AI 额度和图片处理是否单独收费。
5. 收入、房产、生育观等字段的可计算范围、可展示范围和隐私设置联动规则。
6. 是否新增结构化价值观问卷；当前灵魂匹配只使用 MBTI、兴趣和性格标签。
